# N64_MiSTer VR4300 CPU: microarchitecture techniques worth reusing

Source: [MiSTer-devel/N64_MiSTer](https://github.com/MiSTer-devel/N64_MiSTer/tree/eb5554af01bb97bdf3d295aed02a989ac10ccee4) `rtl/` (VHDL-2008, Quartus 17/18, Cyclone V). Links are pinned to the reviewed commit.

## 0. Big picture (read this first)

- **In-order, scalar, 5 stages** (fetch, decode+regread, execute, mem, writeback/retire), 64-bit datapath. Everything is in [`cpu.vhd`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd), and the file is split by `stage 1` to `stage 5` banners ([`cpu.vhd:1011`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L1011), [`1175`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L1175), [`2072`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L2072), [`2814`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L2814), [`3225`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L3225)).
- **The CPU runs at the real VR4300 frequency (93.75 MHz) on its own PLL output** ([`N64.sv:212-221`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/N64.sv#L212-L221), [`pll.v`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/pll.v) outclk_1 = 93.75). The rest of the system runs at clk1x = 62.5 MHz (RCP) and clk2x = 125 MHz (DDR3 side). All three come from one PLL, so they are synchronous and related. `ce_93` is only a savestate pause ([`n64top.vhd:585`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/n64top.vhd#L585)). Cycle accuracy comes from the native clock plus modelled latencies, not from throttling.
- **Global stall vector.** `stall <= '0' & stall4 & stall3 & stall2 & stall1` ([`cpu.vhd:682`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L682)). Every stage advances only when `stall = 0`. The one exception is a masked copy for the mem stage (see section 1). The scheme is very simple, but it creates one high-fanout enable. The QSF turns on physical-synthesis register duplication and retiming to cope ([`N64.qsf`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/N64.qsf): `PHYSICAL_SYNTHESIS_REGISTER_DUPLICATION ON`, `..._RETIMING ON`, `OPTIMIZATION_MODE "AGGRESSIVE PERFORMANCE"`).
- **Long-latency units block the whole pipe** for a fixed number of cycles that matches silicon latency: mult/div, FPU ops, TLB walks, uncached accesses, cache misses. There is no out-of-order completion. This is the main thing a 603e must *not* copy wholesale. The *sub-techniques* are still very reusable.

### Stall/flush propagation
- **Stall is "stop everything"**, and each stage's process wraps its update in `if (stall = 0)`. Freeze all stages at once and nothing is lost. This removes per-stage valid/ready handshakes at the cost of throughput.
- **Mem-stage exemption (clever):** a load in EX sets `stall3` and `executeStallFromMEM`. The mem stage uses `stall4Masked`, which ignores `stall3` when it came from a load, so the load itself still flows into stage 4 while the younger instruction is held ([`cpu.vhd:2876`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L2876)):
  ```vhdl
  stall4Masked <= stall(4 downto 3) & (stall(2) and (not executeStallFromMEM)) & stall(1 downto 0);
  ```
  In practice this gives one load-delay bubble on *every* load, dependent or not ([`cpu.vhd:2780-2783`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L2780-L2783): `stall3 <= '1'; executeStallFromMEM <= '1'`), which releases when `datacache_readdone` arrives ([`2474-2482`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L2474-L2482)). **Trade-off:** the cache output never has to be forwarded into EX in the same cycle it leaves the BRAM, which is good for timing, but every load pays a cycle. A 603e with a real load/store unit should instead forward only for dependent consumers.
- **Flush:** an exception is detected combinationally in EX (`exceptionNew3`, [`cpu.vhd:2223`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L2223)). COP0 registers it as `exception` in the next cycle, and every stage checks `exception = '1'` to drop its payload. Decode drops (`decodeNew <= '0'`, [`cpu.vhd:1237-1239`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L1237-L1239)). Execute clears write, memory and COP0 enables ([`2577-2585`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L2577-L2585)). The faulting instruction suppresses its own writeback with `if (decodeTarget = 0 or exceptionNew3 = '1') then resultWriteEnable <= '0'` ([`2613`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L2613)). The instruction already in mem completes, which makes the design **precise at the EX/MEM boundary**.
- **Operand snooping during stall (best practice):** while decode is stalled, its already-latched operands keep watching the regfile write port. Without this they would go stale ([`cpu.vhd:2056-2064`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L2056-L2064)):
  ```vhdl
  -- operand forwarding in stall
  if (decodeSource1 > 0 and writebackTarget = decodeSource1 and writebackWriteEnable = '1') then decodeValue1 <= writebackData; end if;
  ```
  FPU operands do the same per 32-bit half. This is exactly the "reservation station snoops the result bus" pattern a 603e needs.

### Hazard detection
- **RAW:** handled by the forwarding network below. A load-use hazard needs no detection because every load bubbles.
- **Structural:** long ops set `stall3` (`hiloWait`, FPU `command_done`, TLB `TLB_dataStall`). A full write FIFO sets `stallNew4` ([`cpu.vhd:2920-2925`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L2920-L2925)). A D-cache op, TLBP or TLB miss sets `stall4` ([`3087-3093`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L3087-L3093)).
- **FPU RAW:** there is no FPU-to-FPU forwarding. `decFPUForwardUse` ([`cpu.vhd:1214`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L1214)) compares decode's FPU sources with the in-flight FPU target, and on a match stalls until the FPU writes the regfile. It compares only bits `4:1` (even/odd pair), which is conservative in FR=1 mode but cheap and correct in FR=0.
- **COP0 hazards:**
  - COP0 reads are treated like loads: they stall EX and return data in mem ([`cpu.vhd:2780`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L2780), [`3057-3066`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L3057-L3066)).
  - COP0 writes commit in mem order ([`cpu_cop0.vhd:674`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_cop0.vhd#L674), `elsif (stall4Masked = 0 and executeNew = '1')`), so the instructions behind see a consistent state.
  - An IRQ is not taken while a COP0 write is in EX: `irqTrigger` requires `writeEnable = '0'` ([`cpu_cop0.vhd:345`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_cop0.vhd#L345)).
  - `blockIRQ` is set when the instruction ahead is any COP0 op or a branch-likely ([`cpu.vhd:1705`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L1705), [`1637`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L1637), [`1758`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L1758), [`1800-1815`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L1800-L1815)).
  - Modelled write latencies: `cop0Written9 <= 3` delays the Count restart and `cop0Written6` resets Random two cycles after a Wired write ([`cpu_cop0.vhd:703-711`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_cop0.vhd#L703-L711)).

### Forwarding network (structure and cost)
Three sources, and **every select signal is precomputed one stage early and registered**, so no 5-bit comparator sits in the EX critical path.
1. **EX to EX (result of the previous instruction):** decode compares the *incoming* sources with its own `decodeTarget` and registers a 1-bit select ([`cpu.vhd:1269-1272`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L1269-L1272)):
   ```vhdl
   executeForwardValue1 <= '0';
   if (decSource1 > 0 and decodeTarget = decSource1) then executeForwardValue1 <= '1'; end if;
   ```
2. **MEM to EX (two instructions back, including load results):** computed in the stage-4 process against the decode-stage sources ([`cpu.vhd:3029-3038`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L3029-L3038)), registered as `writebackForwardValue1/2`.
3. **WB to decode (regfile write-through):** the MLAB is `CONSTRAINED_DONT_CARE` for read-during-write, so decode muxes `writebackData` over the RAM output when the addresses match ([`cpu.vhd:1259-1267`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L1259-L1267)).

EX mux ([`cpu.vhd:2078-2084`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L2078-L2084)):
```vhdl
value1 <= resultData    when (executeForwardValue1   = '1' and resultWriteEnable = '1') else
          writebackData when (writebackForwardValue1 = '1') else
          decodeValue1;
```
Cost: two 3:1 64-bit muxes. The late qualifier (`resultWriteEnable`) is a single flop. The RSP core uses the same template with only the EX to EX level ([`RSP_core.vhd:1588-1589`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/RSP_core.vhd#L1588-L1589)).

### Branch handling
- **Resolved in EX with a 1-instruction delay slot, so there is no penalty and no predictor.** The compare (`cmpEqual/cmpZero/cmpNegative`, [`cpu.vhd:2139-2141`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L2139-L2141)) directly selects the next fetch address.
- **Dual next-PC paths with duplicated I-tag RAMs (clever, section 6).** `FetchAddr1` is exception/sequential/JR/J/ERET and `FetchAddr2` is always the branch target ([`cpu.vhd:2143-2166`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L2143-L2166)). Both are looked up in parallel, and the branch outcome `FetchAddrSelect` picks the hit/data late:
  ```vhdl
  -- use two nextaddress/branch paths with 2 tag rams, so different paths can be calculated in parallel to improve timing
  FetchAddrSelect <= '0' when (exception = '1' or ... ) else
                     '1' when (decodeBranchType = BRANCH_BRANCH_BEQ and cmpEqual = '1') else ...
  FetchAddr2 <= PCnextBranch;
  ```
- **Narrowed PC adders (timing hack, and a pitfall):** only the low 29 bits add ([`cpu.vhd:2133-2137`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L2133-L2137): "assume region change cannot/will not happen with counting up or short jumps").
- **Branch-likely:** `EXEIgnoreNext` ([`cpu.vhd:2180-2189`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L2180-L2189)) registers `executeIgnoreNext`, which nullifies the delay slot when it reaches EX by forcing its enables to 0 ([`2593-2602`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L2593-L2602)).
- **Delay-slot tracking for EPC:** `EXEBranchdelaySlot` is registered as `executeBranchdelaySlot` and fed to COP0 as `isDelaySlot`.

## 2. Decode: keeping it off the critical path

- **Decode and regfile read share one cycle.** The regfile read address comes straight from the I-cache BRAM output bits (`opcodeCacheMuxed`, [`cpu.vhd:1179-1190`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L1179-L1190)). That only works because the regfile is an **MLAB with unregistered read address** (section 3).
- **Everything the EX datapath needs is decoded into registered one-hot-ish flags and enums.** Examples are `decodeResultMux` (a 14-way enum), `decodeBranchType`, `decodeExcType` (24 exception-check kinds), `decodeLoadType`, `decodeMemWriteType`, `decodeShiftAmountType` and `decodeUseImmidateValue2`. The giant `case` sits inside the clocked process ([`cpu.vhd:1287-2041`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L1287-L2041)), and defaults are assigned first ([`1286-1335`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L1286-L1335)), which avoids latches and reset cost. EX then runs purely on flops plus datapath.
- **Exception checks are pre-classified.** Decode picks *which* overflow/trap/alignment test applies (`decodeExcType`) and the exception code. EX only evaluates the selected condition ([`cpu.vhd:2223-2248`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L2223-L2248)). One registered enum drives a single big mux, instead of re-decoding the opcode.
- **Datapath sharing chosen at decode:** register/immediate shift amounts share one shifter via `decodeShiftAmountType` ([`2091-2102`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L2091-L2102)). Arithmetic and logical right shifts share one 65-bit arithmetic shifter by muxing bit 64 ([`2097-2099`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L2097-L2099)). 32-bit ops sign-extend at the result mux via `decodeResult32` ([`2210-2211`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L2210-L2211)).
- **The IRQ is injected at decode as a bubble:** `if (irqTrigger = '1' and blockIRQ = '0') then decode_irq <= '1'; decodeNew <= '0';` ([`cpu.vhd:2043-2046`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L2043-L2046)). The IRQ then travels like an instruction and COP0 takes it with EPC = `pcOld1`.

## 3. Register file

- **The GPR file is 2 copies of a 32x64 MLAB**, one per read port, sharing the write port ([`cpu.vhd:953-1000`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L953-L1000)). The wrapper [`RamMLAB.vhd`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/RamMLAB.vhd) instantiates `altdpram` with `ram_block_type => "MLAB"`, `rdaddress_reg => "UNREGISTERED"`, `outdata_reg => "UNREGISTERED"` (async read) and `read_during_write_mode_mixed_ports => "CONSTRAINED_DONT_CARE"` ([`RamMLAB.vhd:30-51`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/RamMLAB.vhd#L30-L51)). The write address, data and enable are registered on `inclock`.
  - **Why MLAB:** async read lets decode read the regfile in the same cycle the opcode leaves the I-cache BRAM. An M10K would add a cycle. CONSTRAINED_DONT_CARE avoids Quartus's slow mixed-port bypass logic, and explicit bypass is done in decode instead.
  - **Cost:** 64 x 32 = 2 Kbit per copy, about 4 MLABs per copy.
- **The FPU regfile is split into LO/HI 32-bit halves with separate write enables** (`FPUregs_wren_a(1 downto 0)`, [`cpu.vhd:876-947`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L876-L947)). This supports FR=0 mode, where 32-bit registers pair into doubles, plus partial writes from LWC1/MTC1, and the decode bypass is done per half ([`1276-1279`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L1276-L1279)).
- **The write-port mux gives savestate load top priority** (`ss_regs_load`, [`cpu.vhd:968-974`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L968-L974)). Savestates therefore restore the regfile through the normal write port, with no extra RAM port.
- **R0:** writes to r0 are suppressed at decode and execute (`decodeTarget = 0`, [`cpu.vhd:2613`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L2613)), and forwarding checks `decSource > 0`. The RAM is never guarded.
- **Sim shadow:** a full `regs` array under `translate_off` mirrors writes for the trace ([`cpu.vhd:3257-3260`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L3257-L3260)), so the export costs no hardware.

## 4. Multiply / divide

- **One 64x64 to 128 DSP multiplier** ([`cpu_mul.vhd`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_mul.vhd), `altera_mult_add`, inputs latched with `input_a0_latency_clock => "CLOCK0"`, `output_register => "CLOCK0"`, dynamic `signa/signb`). Signed and unsigned share it via the sign port. The operands are sign-extended or zero-extended in EX ([`cpu.vhd:2684-2718`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L2684-L2718)).
- **Fixed-latency scheduling that matches silicon:** MULT/MULTU set `hiloWait <= 4` and DMULT sets `7` ([`cpu.vhd:2690-2717`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L2690-L2717)). DIV sets `36` and DDIV sets [`68`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/RSP_core.vhd#L68) ([`2738-2769`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L2738-L2769)). A down-counter releases `stall3` and writes HI/LO on the last cycle ([`2485-2505`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L2485-L2505)). Because the pipe is fully stalled, **no HI/LO interlock logic is needed**: MFHI just reads `HI` in EX (`RESULTMUX_HI`).
- **Pitfall:** the multiplier result is sampled 4 or 7 cycles after the operands are loaded, but **no SDC multicycle is declared** ([`N64.sdc`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/N64.sdc) has only PLL false paths). So the 64x64 has to close in one 10.67 ns period between its input and output registers. On a 603e, either pipeline the multiplier explicitly or add `set_multicycle_path` with a matching enable.
- **Resource sharing between INT and FPU (clever):** for MUL.S/MUL.D, decode flags `decodeFPUMULS/MULD`. EX then loads the *mantissas with the hidden bit* into the same `mul1/mul2` registers ([`cpu.vhd:2721-2735`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L2721-L2735)), and the FPU consumes `mul_result` a few cycles later in its "stage 3" ([`cpu_FPU.vhd:1400-1430`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_FPU.vhd#L1400-L1430)). The FPU owns no multiplier of its own.
  ```vhdl
  mul1 <= 11x"0" & '0' & std_logic_vector(decodeFPUValue1(51 downto 0));
  if (decodeFPUValue1(62 downto 52) > 0) then mul1(52) <= '1'; end if;   -- hidden bit unless denormal/zero
  ```
- **The divider is radix-2 restoring, 1 bit/cycle** ([`divider.vhd:22`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/divider.vhd#L22), `bits_per_cycle = 1`, generic loop). It works on magnitudes and fixes signs combinationally at the output, including MIPS's DIV-by-zero quirk ([`divider.vhd:121-135`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/divider.vhd#L121-L135)). An `is32` flag starts the pointer 32 bits lower, so 32-bit divides finish in about half the time.

## 5. FPU ([`cpu_FPU.vhd`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_FPU.vhd), [`cpu_FPU_sqrt.vhd`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_FPU_sqrt.vhd))

- **Iterative per instruction, not pipelined across instructions.** Each op has its own short stage chain: ADD 3-4 stages ([`cpu_FPU.vhd:1254-1354`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_FPU.vhd#L1254-L1354)), MUL 4 ([`cpu_FPU.vhd:1356-1441`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_FPU.vhd#L1356-L1441)), CVT and toInt 3-4. DIV and SQRT run 1 bit/cycle (26 steps single, 55 double: [`cpu_FPU.vhd:1164-1202`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_FPU.vhd#L1164-L1202), and [`cpu_FPU_sqrt.vhd`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_FPU_sqrt.vhd) non-restoring). The integer pipe stalls until `command_done` ([`cpu.vhd:2785-2787`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L2785-L2787)), so FP and INT never overlap.
- **One copy each of the expensive hardware, shared by all ops:**
  - one 57-bit left/right shifter with sticky "lost bits" ([`cpu_FPU.vhd:1032-1050`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_FPU.vhd#L1032-L1050))
  - one rounding unit implementing all 4 modes ([`1055-1114`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_FPU.vhd#L1055-L1114))
  - one CLZ ([`1017-1029`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_FPU.vhd#L1017-L1029))
  - one "shortcut" writeback path for zero/inf results ([`883-900`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_FPU.vhd#L883-L900))

  The ops time-multiplex these units because only one op is ever in flight. This is a good area pattern for a first 603e FPU.
- **Denormals, NaNs and exceptions:**
  - A denormal input, or a result that would underflow with flush disabled, raises *unimplemented operation* and traps to software. This matches the real VR4300 ([`cpu_FPU.vhd:503-511`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_FPU.vhd#L503-L511), [`974-980`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_FPU.vhd#L974-L980)).
  - Signalling vs quiet NaN is checked by mantissa MSB ([`513-535`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_FPU.vhd#L513-L535)).
  - Invalid results write the MIPS default NaN ([`902-921`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_FPU.vhd#L902-L921)).
  - CSR cause bits clear at op start (`causeReset`), and flags are sticky.
- **Interlock with the integer pipe:**
  - FPU commands are enabled only when `stall = 0 and decodeNew = '1' and exception = '0'` ([`cpu.vhd:2251-2252`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L2251-L2252)).
  - MFC1/CFC1 data comes back combinationally through `transfer_data` into the EX result mux (`RESULTMUX_FPU`).
  - Loads to FP registers write the FPU regfile from stage 4 through `cop1_stage4_*`, and they get write priority over FPU results ([`cpu.vhd:905-915`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L905-L915)).
- **FR bit (SR.FR, `fpuRegMode`):** in FR=0, decode forces source bit 0 to 0 (even pair, [`cpu.vhd:1196-1206`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L1196-L1206)), and a 32-bit load selects the HI or LO half by the target's odd bit ([`3126-3157`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L3126-L3157)). Two 32-bit-wide MLABs with byte-lane-like enables make this nearly free.
- **FPU verification:** there is a sim-only per-op trace, `OP/RM/R1/R2/RS/CSRB/CSRA/CFB/CFA/E`, written to a file for diffing against a softfloat reference ([`cpu_FPU.vhd:1770-1853`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_FPU.vhd#L1770-L1853)).

## 6. Caches

### I-cache ([`cpu_instrcache.vhd`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_instrcache.vhd)): 16 KB, direct-mapped, 32 B lines, physically tagged, virtually indexed
- **Tags are in MLAB with async read** (512 x 21: 20-bit PA tag + valid), so the tag compare finishes in the same cycle the fetch address is formed ([`cpu_instrcache.vhd:92-109`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_instrcache.vhd#L92-L109)). The compare runs against the **µITLB-translated** address (`read_addrCompare1`, [`cpu.vhd:1061-1062`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L1061-L1062)). Translation and tag read proceed in parallel: VIPT with index bits 13:5.
- **Two tag RAM copies** for the two candidate next PCs (section 1). `read_hit <= read_hit2 when read_select = '1' else read_hit1` ([`89`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_instrcache.vhd#L89)). The data RAM (M10K) address is muxed by the same late select ([`186-188`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_instrcache.vhd#L186-L188)). The M10K registers its address, so the data arrives the next cycle, straight into decode.
- **The data RAM is mixed-width true dual-port** (`dpram_dif`): 64-bit write port on **clk2x (DDR3 side)**, 32-bit read port on clk93 ([`163-184`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_instrcache.vhd#L163-L184)). **The line fill writes the BRAM straight from `ddr3_DOUT`** in the memory clock domain. There is no fill buffer and no CDC FIFO: the BRAM is the clock crossing and the width converter ([`141-161`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_instrcache.vhd#L141-L161)).
- **No critical-word-first.** The fill starts at the line base (`cache_addr_a <= fill_addrTag_2x & "00"`). The fetch restarts only after `ram_done`, then re-reads from the cache ([`240-248`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_instrcache.vhd#L240-L248), [`cpu.vhd:1112-1117`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L1112-L1117)).
- **Holding BRAM output across a stall:** the I-cache read port is not clock-enabled by stall. Instead, on the first stall cycle after a hit, the output is copied into `opcode0` and decode switches to it ([`cpu.vhd:1106-1110`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L1106-L1110)):
  ```vhdl
  cacheHitLast <= instrcache_hit;
  if (useCached_data = '1' and cacheHitLast = '1' and stall(4 downto 1) > 0 and stall1 = '0') then
     useCached_data <= '0';
     opcode0        <= unsigned(instrcache_data);
  ```
- **CACHE ops:** index-store-tag writes TagLo. Index-invalidate and hit-invalidate are implemented as an unconditional index clear ([`cpu_instrcache.vhd:216-219`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_instrcache.vhd#L216-L219), "HACK! todo: should only clear if tag matches"). **Pitfall:** it passes games but is not architecturally correct.
- **Reset and savestate:** a `CLEARCACHE` state walks all 512 tags ([`233-239`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_instrcache.vhd#L233-L239)).

### D-cache ([`cpu_datacache.vhd`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_datacache.vhd)): 8 KB, direct-mapped, 16 B lines (2 x 64 bit), write-back, write-allocate
- **The tag RAM is an M10K (`dpram`, 512 x 22: tag + valid + dirty) and its read is launched one stage early.** The address is the *virtual* EX-stage AGU output (`tag_addr => EXECacheAddr`, [`cpu.vhd:2849`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L2849)). The compare happens in mem against the *translated* `executeMemAddress` ([`cpu_datacache.vhd:212`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_datacache.vhd#L212)). The M10K's own input register therefore serves as the EX/MEM pipeline register.
- **Stall handling on the tag RAM uses the BRAM clock enable:** `clken_b => ce_fetch` with `ce_fetch <= stall = 0 and ce_93` ([`149`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_datacache.vhd#L149), [`178`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_datacache.vhd#L178)). The output simply holds during a stall. This is cheaper than a hold register.
- **Tag write-to-read bypass:** if a tag write targets the index currently being read, the new tag is captured and muxed in (`tag_newEna/tag_newData`, [`187`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_datacache.vhd#L187), [`325-340`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_datacache.vhd#L325-L340)). This is needed because the M10K read was launched a cycle before the write landed.
- **The data array is 8 byte-lane M10Ks** (8 x 1024 x 8, [`247-268`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_datacache.vhd#L247-L268)). Each lane has its own write enable from `write_be`, and port A (clk2x) is filled straight from DDR3 like the I-cache. The data RAM address picks the next-instruction address when advancing, and the held address when stalled or writing ([`270-272`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_datacache.vhd#L270-L272)).
- **Store hit is single-cycle:** it writes data and sets the dirty bit in the tag in the same cycle ([`282`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_datacache.vhd#L282), tag write at [`cpu_datacache.vhd:151-160`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_datacache.vhd#L151-L160)). A load immediately after a store costs one cycle (`READWAIT`, [`400`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_datacache.vhd#L400)), because the port was busy writing.
- **Miss with dirty victim:** `WRITEBACK1ADDR` then `..READ` then `..WRITE` then `WRITEBACK2WRITE` pushes two 64-bit beats into the CPU write FIFO, gated by `fifo_block`. `FILL` follows ([`379-385`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_datacache.vhd#L379-L385), [`489-523`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_datacache.vhd#L489-L523)). The victim is written back *before* the fill, so no victim buffer is needed.
- **CACHE ops:** index-WB-invalidate, index-load-tag, index-store-tag, create-dirty-exclusive, hit-invalidate, hit-WB-invalidate and hit-WB are all implemented from the tag compare in `IDLE` ([`405-457`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_datacache.vhd#L405-L457)), with TagLo transfer through `writeTagEna/writeTagValue` to COP0.
- **Debug and accuracy knobs:** `slow_in` adds N wait cycles on read hits (`WAITSLOW`, [`396-399`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_datacache.vhd#L396-L399)) to tune timing against hardware. `force_wb_in` turns the cache write-through for debugging. Both come from OSD status bits.
- **Uncached accesses** bypass the cache and go through the write FIFO (section 10). Cached vs uncached is decided in EX from the segment or the µTLB C bits ([`cpu.vhd:2661-2669`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L2661-L2669)).

**How hits are made "single-cycle at fmax":**
1. The tag read starts in EX from the untranslated address; only the compare is in MEM.
2. The I-side uses MLAB async tags and duplicated tag RAMs.
3. Data RAM outputs feed registered consumers only; the load result is registered in `writebackData`.
4. Load data is never forwarded from the BRAM output into EX in the same cycle, because every load takes the bubble.

## 7. TLB ([`cpu_cop0.vhd`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_cop0.vhd), [`cpu_TLB_instr.vhd`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_TLB_instr.vhd), [`cpu_TLB_data.vhd`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_TLB_data.vhd))

- **The 32-entry JTLB is not a CAM.** It is a **32 x 101-bit MLAB searched sequentially, one entry per cycle** ([`cpu_cop0.vhd:1154-1167`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_cop0.vhd#L1154-L1167), state machine [`920-1030`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_cop0.vhd#L920-L1030)). This is the key area trick: 32 parallel comparators with page-mask logic would be large and slow.
  - The search starts at the **last hit index** (`TLB_readAddr <= TLB_fetchSource; TLB_compareEnd <= TLB_fetchSource - 1`, [`945-957`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_cop0.vhd#L945-L957)), so locality makes most walks 1-2 cycles. The worst case is 32.
  - Page-mask handling is per entry: `TLB_checkMask`, `TLB_addMask`, and even/odd bank select from `(pagemask+1) & VA` ([`1098-1110`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_cop0.vhd#L1098-L1110)).
  - TLBP also walks sequentially (`TLBPROBE`, [`966-983`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_cop0.vhd#L966-L983)). TLBR is a single-cycle read, because the read address is `Index` when idle ([`1169`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_cop0.vhd#L1169)).
- **Micro-TLBs provide single-cycle translation in the pipeline:**
  - ITLB: **1 entry** ([`cpu_TLB_instr.vhd:68`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_TLB_instr.vhd#L68)).
  - DTLB: **4 entries**, fully associative, round-robin replacement ([`cpu_TLB_data.vhd:57`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_TLB_data.vhd#L57), [`181`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_TLB_data.vhd#L181)).
  - The DTLB compare runs combinationally on `calcMemAddr` in EX ([`cpu.vhd:3402`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L3402)). The translated PA is registered into `executeMemAddress` ([`2565-2571`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L2565-L2571)).
  - **The dirty bit is folded into the hit:** a store to a clean page is a µTLB miss, and the JTLB walk then raises TLB Mod ([`cpu_TLB_data.vhd:88`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_TLB_data.vhd#L88)).
    ```vhdl
    if (TLB_IsWrite = '0' or miniEntries(i).dirty = '1') then mini_hit <= '1'; ...
    ```
- **Miss handling:** `TLB_Stall` sets `stall1`/`stall3`. The µTLB issues `TLB_fetchReq` to the COP0 walker. I-side and D-side requests are latched as `*_fetchReq_saved`, so they can queue ([`cpu_cop0.vhd:907-908`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_cop0.vhd#L907-L908)). On done the µTLB fills its entry and pulses `TLB_UnStall`, and the pipeline resumes with `TLB_*AddrOutLookup` ([`cpu.vhd:1124-1136`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L1124-L1136), [`2525-2547`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L2525-L2547)). If the walk failed, the µTLB enters its `EXCEPTION` state and the exception is raised.
- **Coherence:** TLBWI/TLBWR and any ASID change pulse `TLBInvalidate`, which clears all µTLB entries ([`cpu_cop0.vhd:711-720`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_cop0.vhd#L711-L720), [`910-912`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_cop0.vhd#L910-L912)). This avoids tracking which µTLB entry came from which JTLB slot.
- **TLB write path:** the write data is assembled combinationally from EntryHi/Lo0/Lo1/PageMask ([`1114-1147`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_cop0.vhd#L1114-L1147)). A single write port is muxed between TLBWI (Index), TLBWR (Random) and `TLB_init`, which covers reset and savestate load ([`1148-1152`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_cop0.vhd#L1148-L1152)).
- **Timing compromises:**
  - The 64-bit region decode uses only the base register `value1`, not base+offset, "for timing purposes" ([`cpu.vhd:2257-2259`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L2257-L2259)).
  - The address-error check likewise avoids `calcMemAddr` ([`2217`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L2217), "can't do that due to timing closure").
  - 64-bit I-fetch mapping is restricted "to not screw up FPGA route timing" ([`1066`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L1066)).
  - **Pitfall:** these are silent architectural deviations. On a 603e, prefer adding a pipeline stage or doing the check one cycle later with a precise exception.

## 8. Exceptions / interrupts

- **Where detected:**
  - fetch: ITLB, as `exceptionStage1`
  - EX: `exceptionNew3`, covering overflow, trap, syscall/break, reserved instruction, address error and coprocessor unusable
  - DTLB: raised while stalled in EX
  - FPU: `exceptionFPU` at `command_done`
  - IRQ: decode bubble
- **Priority** is a fixed if/elsif chain in COP0 ([`cpu_cop0.vhd:844-866`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_cop0.vhd#L844-L866)): IRQ > FPU > TLB-read > TLB-write > TLB-mod > EX exception. It only runs when `stall = 0` or the source is one that arrives during a stall.
- **EPC and delay slots** ([`cpu_cop0.vhd:808-829`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_cop0.vhd#L808-L829)):
  ```vhdl
  nextEPC := pcOld1;
  if (isDelaySlot = '1') then nextEPC := pcOld1 - 4; end if;
  if (exceptionNewPC = '1') then nextEPC := exceptionPCStore; end if;
  ```
  EPC and BD are latched one cycle before `exception` (`nextEPC_1`, `isDelaySlot_1`). A fetch-stage TLB exception computes EPC from the fetch address, minus 4 if `nextDelaySlot` ([`821-828`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_cop0.vhd#L821-L828)). A JR/JALR to a misaligned target is special: the delay slot is allowed to execute first (`exceptionAllowDelay`, [`cpu.vhd:2645-2648`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L2645-L2648)).
- **Killing in-flight instructions:** covered in section 1. The key detail is that `FetchAddr1` becomes `exceptionPC` the cycle `exception` is high, and all enables in decode and EX are cleared. Vector selection (BEV, TLB-refill 0x000/0x080 vs general 0x180) is computed *every cycle* into a register `exceptionPC` ([`cpu_cop0.vhd:489-519`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_cop0.vhd#L489-L519)). The vector is therefore a flop and never a late mux.
- **Count/Compare:** Count is 33 bits and increments every CPU cycle. Software sees `COUNT(32 downto 1)`, which gives the architectural half-rate Count without a divider or enable ([`cpu_cop0.vhd:390`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_cop0.vhd#L390), [`620-628`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_cop0.vhd#L620-L628)). The Compare match sets IP7, and a Compare write clears it. `cop0FirstWrite9` is a game-compatibility fudge that compensates for RDRAM init time ([`710`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_cop0.vhd#L710)). Count restores from the savestate ([`548`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_cop0.vhd#L548)).

## 9. Timing / fmax techniques

- **SDC:** the CPU has no multicycle or false paths. [`N64.sdc`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/N64.sdc) only cuts the asynchronous video PLL (pll2) and HPS/HDMI/audio clocks. **The clk93, clk1x and clk2x crossings are timed as synchronous related clocks.** 62.5 and 93.75 MHz have a 5.33 ns worst edge separation, so every crossing is a plain flop-to-flop or flop-to-MLAB-to-flop path:
  - the CPU write FIFO is written on clk93 and its `Dout`/`Empty` are read on clk1x ([`cpu.vhd:788-806`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L788-L806), [`824-858`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L824-L858))
  - `mem_done` is sampled on clk93 with edge detect ([`771-783`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L771-L783))
  - the read strobe crosses clk1x to clk93 as a toggle/edge ([`697-701`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L697-L701))
  - the fill address crosses clk93 to clk1x to clk2x through two registers ([`cpu_instrcache.vhd:136-147`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_instrcache.vhd#L136-L147))
  - `done/granted` pulses are stretched to 2 clk2x cycles, so clk1x sees them ([`DDR3Mux.vhd:255-264`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/DDR3Mux.vhd#L255-L264), `use2Xclock & '1'`)
- **Choose frequencies so that every domain is a rational multiple of one PLL VCO, then treat crossings as synchronous.** This works, but only with short crossing paths. It cannot be applied to asynchronous HPS or DDR clocks.
- **Pipelined or registered paths called out in comments:** duplicated I-tag RAMs for the parallel next-PC paths, the region check on the base register only, narrowed PC adders, and the D-tag read launched from EX.
- **Precomputed forwarding selects** and **registered exception vectors** keep comparators and muxes out of the EX loop.
- **Register-input "early" signals:** COP0 status such as `privilegeMode`, `bit64region` and `COP1_enable` is registered (`bit64mode` is recomputed each cycle from SR, [`cpu_cop0.vhd:788-798`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_cop0.vhd#L788-L798)). `DATACACHEON_intern`, `DISABLE_DTLBMINI_INTERN` and `DISABLE_BOOTCOUNT_INTERN` re-register OSD inputs, so they never reach deep logic from a far-away pin ([`cpu.vhd:2981-2982`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L2981-L2982)).
- **QSF:** aggressive performance, physical-synthesis combo, register duplication and retiming, and `ALLOW_POWER_UP_DONT_CARE`. Nearly every signal has `:= '0'` power-up values, and reset is used only for control, not the datapath.
- **Cycle accuracy without throttling:**
  - native 93.75 MHz clock
  - fixed mult/div counts (section 4)
  - per-region minimum bus latency in [`memorymux.vhd`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/memorymux.vhd) (`bus_slow`, e.g. PI cart read 137, PIF RAM 1910: [`320-455`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/memorymux.vhd#L320-L455))
  - DDR3 `slow_in`
  - D-cache `slow_in`

  `FASTBUS` and `FASTRAM` switches bypass the modelled latency ([`memorymux.vhd:474`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/memorymux.vhd#L474), [`490`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/memorymux.vhd#L490)).

## 10. Memory bus

- **CPU side: one 8-entry fall-through MLAB FIFO carries all stage-1 and stage-4 requests** ([`cpu.vhd:688-806`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L688-L806)). That covers uncached stores, uncached loads, D-cache fills, D-cache writebacks, I-cache fills and uncached fetches. The 108-bit entry is 64 data + 32 addr + 8 BE + stage flag + r/w + 64-bit flag + cache flag. **Because stores, loads and fills share one in-order queue, memory ordering is automatic.** A load can never overtake an older posted store, so no store-to-load address checks are needed.
- **Arbitration inside the CPU:** the fixed priority is D-writeback > stage-4 store/load/fill > stage-1 fetch. A stage-1 request that collides with a stage-4 request is latched (`mem1_request_latched`) and pushed next cycle ([`cpu.vhd:710-715`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L710-L715), [`753-763`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L753-L763)).
- **Early full:** `writefifo_block` fires at count >= 4 (or 3 + write in flight) in the 8-deep FIFO ([`cpu.vhd:807`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L807)). That leaves room for requests already committed. `error_fifo` is wired to the FIFO `Full` flag, which is a hardware assertion.
- **Bus master (clk1x):** a 2-state machine pops the FIFO, issues `mem_request` with `mem_size` = 1, 2 (D-line) or 4 (I-line) beats, and waits for `mem_done` ([`cpu.vhd:817-869`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L817-L869)).
- **memorymux (clk1x):** a combinational address decode fans out to about 11 register-bus slaves. **The read data is a wired-OR** of all slave outputs, and each slave drives 0 when not selected ([`memorymux.vhd:272-275`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/memorymux.vhd#L272-L275)). The RDRAM path forwards to DDR3Mux with burstcount = `mem_size`.
- **DDR3Mux (clk2x):**
  - Port selection is a fixed priority loop: the highest index wins ([`DDR3Mux.vhd:244-265`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/DDR3Mux.vhd#L244-L265)).
  - Posted-write FIFOs (RSP, PI, RDP, RDP-Z, VI) interleave with direct read requests. RSP DMA gets a burst "hold" state (`RSPFIFO`).
  - Read bursts are split into chunks of up to 255 beats (`READAGAIN`, [`408-420`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/DDR3Mux.vhd#L408-L420)).
  - A timeout watchdog raises `error` ([`382-385`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/DDR3Mux.vhd#L382-L385)).
  - Accesses above the configured RAM size are clamped or dropped, with an error flag ([`327-341`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/DDR3Mux.vhd#L327-L341)).
- **Latency hiding:**
  - The cache fill streams straight into the cache BRAM on clk2x as `ddr3_DOUT_READY` beats arrive, with `rdram_granted2X` starting the address counter. This saves the clk2x-to-clk1x-to-clk93 hop for the bulk data. Only the `done` pulse crosses.
  - Posted stores never stall the CPU until the FIFO is half full.
  - There is no critical-word-first and no hit-under-miss.

## 11. Debug / verification

- **Retirement trace ([`export.vhd`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/export.vhd), sim only):**
  - Stage 5 emits a `cpu_export` record on every retired instruction: PC, opcode, 32 GPRs, 32 FPRs, 32 COP0 regs, HI, LO, CSR ([`cpu.vhd:3264-3285`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L3264-L3285)).
  - PC and opcode travel down a **sim-only shadow pipeline** (`pcOld2..4`, `opcode2..4`, `hi_1/2` inside `translate_off`, [`cpu.vhd:157-173`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L157-L173)), so the hardware carries nothing extra.
  - Each line is written in **delta format**: `PC xxx OP xxx` plus only the registers that changed, e.g. `R05 ...`, `C12 ...`, `F03 ...`, `HI`, `LO`, `CSR` ([`export.vhd:209-257`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/export.vhd#L209-L257)).
  - COP0 Random (1) and Count (9) are excluded because they are nondeterministic against an emulator ([`export.vhd:224`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/export.vhd#L224)).
  - The file rolls over every 10M instructions ([`export.vhd:255-258`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/export.vhd#L255-L258)). Optional generics add an instruction index and cycle stamps (`export_index`, `export_time`).
  - Because the format is lower-case hex, the emulator can be patched to emit the identical format and the two files diffed line by line.
- **Unit-level sim traces** for the D-cache (Fill/Read/Store/Writeback lines with tag, index and data, [`cpu_datacache.vhd:545-722`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_datacache.vhd#L545-L722)) and the FPU (per-op operands, result and CSR before/after, [`cpu_FPU.vhd:1770-1853`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_FPU.vhd#L1770-L1853)). Each unit is checked against the emulator's model of that unit, so divergence is localized to a unit before full-system traces are needed.
- **Sim-only performance counters:**
  - stall cycles per stage: `stallcountNo/1/3/4/DMA` ([`cpu.vhd:3590-3605`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L3590-L3605))
  - µTLB hit/stall statistics in `ganalyze` generate blocks ([`cpu_TLB_instr.vhd:170-207`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_TLB_instr.vhd#L170-L207))
- **Hardware assertions shown in the OSD:**
  - Sticky `errorCode` bits collect `error_instr` (unknown opcode), `error_stall` (13-bit stall watchdog), `error_FPU`, `error_exception` (address, reserved and trap exceptions), `error_fifo` and `error_TLB` (a TLB op issued while a walk is busy) ([`cpu.vhd:3574-3585`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L3574-L3585), [`n64top.vhd:590-609`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/n64top.vhd#L590-L609)).
  - This is invaluable on real hardware, where there is no SignalTap budget.
- **Savestate or emulator-state injection (a great technique):** every architectural register's **reset value comes from an `ss_in` array** filled over the savestate bus:
  - PC ([`cpu.vhd:1086-1095`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L1086-L1095)), HI/LO ([`2453-2454`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L2453-L2454)), COP0 SR/EPC/Count/Compare/Wired/Config ([`cpu_cop0.vhd:528-600`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_cop0.vhd#L528-L600)), FPU CSR ([`cpu.vhd:3477-3478`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L3477-L3478))
  - the GPRs and FPRs are streamed through the regfile write port ([`cpu.vhd:3505-3528`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L3505-L3528))
  - the TLB goes in through `TLB_init` ([`cpu_cop0.vhd:1071-1094`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_cop0.vhd#L1071-L1094))

  Loading a state is then "write `ss_in` + pulse reset". No second datapath is needed for restore. A sim can start from an emulator dump at any frame, which skips minutes of boot. `SS_reset` also re-inits the caches and TLB by walking indices (`CLEARCACHE`, `TLB_resetMode`). Savestate *save* is stubbed out in this core (`SS_DataRead_CPU <= 0`, [`cpu.vhd:3550`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L3550)), so the mechanism is mainly used for load and debug.
- **Debug knobs brought out as ports:** `RANDOMMISS` forces µITLB misses (disabled), and `DISABLE_DTLBMINI`, `DATACACHESLOW`, `DATACACHEFORCEWEB`, `INSTRCACHEON`, `DATACACHEON` and `DATACACHETLBON` are exposed too. Every performance structure can therefore be switched off at runtime to bisect a bug.

## 12. Other HDL techniques

- **Generic RAM wrappers:**
  - [`RamMLAB.vhd`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/RamMLAB.vhd): MLAB, async read, don't-care read-during-write
  - `dpram` and `dpram_dif`: M10K true dual-port, mixed width, separate clocks, `clken` per port, `NEW_DATA_NO_NBE_READ` ([`dpram.vhd:33-67`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/dpram.vhd#L33-L67), [`169-250`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/dpram.vhd#L169-L250))
  - `SyncRamDualByteEnable`

  Writing vendor-primitive wrappers with explicit `ram_block_type` and RDW modes removes inference ambiguity for the three RAM flavours a CPU needs: MLAB async regfile, M10K registered cache, and mixed-width fill.
- **[`SyncFifoFallThroughMLAB.vhd`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/SyncFifoFallThroughMLAB.vhd):** a show-ahead FIFO on MLAB async read. `Dout` is valid whenever `!Empty`, so the consumer pops and uses data in the same cycle. `NearFull`/`NearEmpty` thresholds are generics, computed from the *next* count ([`78-117`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/SyncFifoFallThroughMLAB.vhd#L78-L117)). Use this for store queues and request queues.
- **Record-based export package** (`pexport`) with a constant initializer lets a large debug bundle cross hierarchy as one port inside `translate_off`.
- **Clock-enable for pause** (`ce_93`) instead of clock gating. Every stage process is `elsif (ce_93 = '1')`, so savestate pause freezes the CPU cleanly.
- **Many small enums** (`t_decodeResultMux`, `CPU_LOADTYPE`, ...) instead of raw bit fields keep decode readable, and Quartus re-encodes them.
- **RSP_core.vhd reuses the same 5-stage skeleton** (same MLAB regfiles, same `stall` vector, same EX forward mux), with vector registers split hi/lo in MLABs. One notable hack is "feed dmem datamux via MFC2 data by hijacking the operand forward bus" ([`RSP_core.vhd:1450-1456`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/RSP_core.vhd#L1450-L1456)), which reuses a forwarding path to inject zeros instead of adding a mux. Nothing else is distinct.

## Top transferable lessons for a 603e core

Ranked by expected value for a dual-dispatch, renamed, cached-MMU 603e on Cyclone V.

1. **Register forwarding and bypass select bits one stage early; never compare register numbers in the execute cycle.**
   - *Why:* it removes 5-bit comparators and priority logic from the ALU-to-ALU loop, which is usually the fmax limiter.
   - *Evidence:* [`cpu.vhd:1269-1272`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L1269-L1272) (EX to EX select in decode), [`3029-3038`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L3029-L3038) (MEM to EX select), [`2078-2084`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L2078-L2084) (EX mux uses only flops).
   - *603e:* at dispatch, compute per-operand "source is rename slot N / result bus K" one-hot tags and register them. The issue/EX mux then selects on registered one-hots. With 2-wide dispatch plus intra-pair dependency, compute pair-internal forwarding at decode as well.

2. **Operands captured before a stall must keep snooping the write/result buses until they issue.**
   - *Why:* a correctness bug otherwise; a value latched at decode goes stale while it waits.
   - *Evidence:* [`cpu.vhd:2056-2064`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L2056-L2064) (GPR) and [`2060-2063`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L2060-L2063) (FPR per-half).
   - *603e:* reservation stations and rename-buffer readers must snoop every result bus each cycle, including the cycle they are written. Make this a checklist item in every issue-queue design.

3. **Use MLAB async-read regfiles, one copy per read port, with explicit write-through bypass.**
   - *Why:* regfile read fits in the decode cycle, directly from the I-cache BRAM output. `CONSTRAINED_DONT_CARE` avoids slow vendor bypass logic.
   - *Evidence:* [`RamMLAB.vhd:30-51`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/RamMLAB.vhd#L30-L51), [`cpu.vhd:953-1000`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L953-L1000), bypass at [`1259-1267`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L1259-L1267).
   - *603e:* the GPR file plus rename buffers need about 4-5 read ports for two dispatches (rA, rB, rS and more). Use N MLAB copies sharing the write ports. Two write ports would need a LVT or bank split. Split the FPR file into 32-bit halves only if single-precision partial writes are wanted; for PPC use 64-bit FPRs.

4. **Separate a small single-cycle µTLB from a large, slow, RAM-based main TLB that is searched sequentially from the last hit.**
   - *Why:* a 32- to 64-entry CAM on FPGA is expensive and slow. A 1-entry ITLB and a 4-entry DTLB give nearly all hits in one cycle, and misses cost a few cycles thanks to "start at last hit".
   - *Evidence:* [`cpu_TLB_data.vhd:57-100`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_TLB_data.vhd#L57-L100), [`cpu_TLB_instr.vhd:68-70`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_TLB_instr.vhd#L68-L70), [`cpu_cop0.vhd:920-1030`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_cop0.vhd#L920-L1030) (sequential walk, `TLB_fetchSource`).
   - *603e:* the 603e has 64-entry 2-way set-associative ITLB/DTLB, indexed by EA bits, so a set-associative TLB is already BRAM-friendly and needs no sequential walk. Keep the µTLB idea anyway, and put the **BATs (4 I + 4 D, fully associative) in parallel with the µTLB** in the AGU cycle. Fold the protection/C/changed-bit check into the µTLB hit (lesson 11).

5. **Invalidate the whole µTLB on any TLB write or context change instead of tracking back-references.**
   - *Why:* it is trivially correct and costs almost nothing, because the µTLB refills in a few cycles.
   - *Evidence:* [`cpu_cop0.vhd:711-720`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_cop0.vhd#L711-L720) (ASID change), [`910-912`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_cop0.vhd#L910-L912) (TLBWI/WR), [`cpu_TLB_data.vhd:127-131`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_TLB_data.vhd#L127-L131).
   - *603e:* flush the µTLB and BAT-match caches on `tlbie`, `tlbia`, any `mtspr` to BATs or SDR1, `mtsr`/`mtsrin`, and MSR[IR/DR/PR] changes.

6. **Launch the D-cache tag and data BRAM read from the untranslated AGU address in EX, and compare against the translated address in MEM (VIPT).** Use the M10K `clken` to hold outputs during stalls, and add a tag write-to-read bypass.
   - *Why:* the BRAM input register becomes the pipeline register, and translation overlaps the RAM access.
   - *Evidence:* [`cpu.vhd:2849`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L2849) (tag_addr from EX), [`cpu_datacache.vhd:149`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_datacache.vhd#L149), [`178`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_datacache.vhd#L178) (clken), [`187`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_datacache.vhd#L187), [`325-340`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_datacache.vhd#L325-L340) (tag bypass), [`212`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_datacache.vhd#L212) (compare with PA).
   - *603e:* the 603e's 16 KB 4-way D-cache with 4 KB pages gives index bits 11:5, which lie inside the page offset, so there is no aliasing and this works perfectly. Duplicate the tag RAM per way, and do the way-select mux in MEM.

7. **Evaluate the two candidate fetch addresses (sequential and branch target) in parallel, with duplicated I-tag RAMs, and select late with the branch outcome.**
   - *Why:* the tag compare no longer waits for the branch compare, which is a documented timing fix.
   - *Evidence:* [`cpu.vhd:2143-2166`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L2143-L2166), [`cpu_instrcache.vhd:87-109`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_instrcache.vhd#L87-L109), [`186-188`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_instrcache.vhd#L186-L188).
   - *603e:* the 603e fetches 2 instructions per cycle and resolves branches early in the BPU with static prediction. Look up predicted-taken and fall-through in parallel, and select with the prediction (and later with the resolve). MLAB tags make the duplicate copy cheap.

8. **Fill caches directly from the memory-controller data beats into port A of a true dual-port (mixed-width) BRAM in the memory clock domain; the CPU reads port B.**
   - *Why:* no fill buffer, no CDC FIFO, and no width converter; the BRAM does all three.
   - *Evidence:* [`cpu_instrcache.vhd:136-184`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_instrcache.vhd#L136-L184), [`cpu_datacache.vhd:228-268`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_datacache.vhd#L228-L268).
   - *603e:* 60x-bus beats (64-bit) write 32 B lines straight into the cache ways. **Improve on it** with critical-word-first: record which beats have landed with a per-line valid mask, and restart the pipe on the first needed beat. The 603e bus does critical-double-word-first bursts, which this design does not exploit.

9. **Put all outbound memory traffic in one in-order request FIFO,** so stores, uncached loads, castouts and fills keep their order and load/store ordering needs no address comparators. Assert the full signal early, with headroom for requests already committed.
   - *Evidence:* [`cpu.vhd:688-806`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L688-L806) (unified FIFO, stage-1 collision latch at [`710-715`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L710-L715)), [`807`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L807) (`>= 4 of 8`).
   - *603e:* the 60x BIU queue can start this way. Later split it into load-miss and store/castout queues with an address-match check when you want hit-under-miss. Keep the early-full margin equal to the maximum number of in-flight requests.

10. **Make savestate and emulator-state injection work through reset values and existing write ports.**
    - *Why:* start simulation from any emulator snapshot with no extra datapath. It also covers reset.
    - *Evidence:* [`cpu.vhd:1086-1095`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L1086-L1095), [`2453-2454`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L2453-L2454), [`3495-3528`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L3495-L3528), [`cpu_cop0.vhd:528-600`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_cop0.vhd#L528-L600), TLB init [`1036-1094`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_cop0.vhd#L1036-L1094) (cop0).
    - *603e:* define a `ss_in[]` SPR image (MSR, SRR0/1, SPRGs, BATs, SDR1, SRs, DEC, TB, HID0, FPSCR, XER, CR, LR, CTR). Mux the GPR/FPR regfile write port for restore, and walk the TLB and cache tags to init them. Pair this with a Dolphin- or PearPC-style state dump.

11. **Fold protection and "must-take-slow-path" bits into the µTLB hit signal.**
    - *Why:* a store to a clean page misses, and the slow path raises the right exception. The fast path stays one AND gate.
    - *Evidence:* [`cpu_TLB_data.vhd:88`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_TLB_data.vhd#L88).
    - *603e:* treat store with C=0 (changed bit), PP/Key protection failure and WIMG I=1 or W=1 as µTLB miss or slow-path. The 603e takes a software TLB-miss exception anyway (it has no HW table walk), so the slow path can be small.

12. **Use a delta-format per-retirement trace generated from a sim-only shadow pipeline, and exclude nondeterministic registers.**
    - *Evidence:* [`export.vhd:209-257`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/export.vhd#L209-L257), [`224`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/export.vhd#L224), shadow pipeline [`cpu.vhd:157-173`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L157-L173), [`3232-3285`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L3232-L3285), per-unit traces [`cpu_datacache.vhd:545-722`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_datacache.vhd#L545-L722), [`cpu_FPU.vhd:1770-1853`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_FPU.vhd#L1770-L1853).
    - *603e:* trace `PC OP` plus changed GPR/FPR/CR/XER/LR/CTR/MSR/SRR, excluding DEC and TB. Add per-unit traces for the D-cache, FPU and MMU (TLB-miss, BAT-hit) to localize divergence. With out-of-order completion, trace at **completion-queue retirement**, not writeback.

13. **Precompute exception vectors and architectural "mode" signals into registers every cycle.**
    - *Evidence:* [`cpu_cop0.vhd:489-519`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_cop0.vhd#L489-L519) (`exceptionPC`), [`788-798`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_cop0.vhd#L788-L798) (`bit64mode`), re-registered option inputs [`cpu.vhd:2981-2982`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L2981-L2982).
    - *603e:* register the MSR-derived IR/DR/PR/FP/IP (vector base 0x000 vs 0xFFF00000) and the next vector address, so the flush path is a flop into the fetch mux.

14. **Share one wide multiplier between integer and FP mantissa multiply,** and share one shifter, one rounder and one CLZ across all FP ops while the FPU is iterative.
    - *Evidence:* [`cpu.vhd:2721-2735`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L2721-L2735), [`cpu_FPU.vhd:1017-1114`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_FPU.vhd#L1017-L1114), [`1400-1430`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_FPU.vhd#L1400-L1430).
    - *603e:* the 603e FPU is pipelined (3-cycle fmadd), with a single multiplier that is 2-pass for double precision. Build a 53x27 multiplier array that serves both `mullw`/`mulhw` (multi-pass) and FP, if the integer multiplier latency budget allows it. The shared-rounder pattern still applies. **Do not** copy the FP-blocks-integer interlock; the 603e must overlap FP with integer.

15. **Model cycle-accurate latencies with explicit counters, and bring out "fast" override switches.**
    - *Evidence:* [`cpu.vhd:2485-2505`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L2485-L2505), [`2690-2769`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L2690-L2769) (hiloWait), [`memorymux.vhd:320-455`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/memorymux.vhd#L320-L455), [`474`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/memorymux.vhd#L474), [`490`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/memorymux.vhd#L490) (bus_slow, FASTBUS/FASTRAM), [`cpu_datacache.vhd:396-399`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_datacache.vhd#L396-L399) (slow_in).
    - *603e:* for GameCube/Wii-class accuracy, set divide latencies (divw is 37 cycles on the 603e) and bus latencies with counters, and provide OSD fast modes.

16. **Put sticky hardware error flags plus a stall watchdog into the OSD.**
    - *Evidence:* [`cpu.vhd:3574-3585`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L3574-L3585), [`n64top.vhd:590-609`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/n64top.vhd#L590-L609), [`DDR3Mux.vhd:382-385`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/DDR3Mux.vhd#L382-L385).
    - *603e:* flags for unknown opcode, completion-queue no-progress for 4K cycles, BIU timeout, FIFO overflow and illegal MMU state. They are cheap and vital on hardware.

17. **Hold stalled BRAM outputs with one of two methods.** Either (a) clock-enable the BRAM port with `!stall` (D-tag), or (b) copy the output into a hold register on the first stalled cycle and mux it (I-cache `opcode0`). Choose per port, depending on whether the port address must keep moving during the stall, for example during a fill.
    - *Evidence:* [`cpu_datacache.vhd:178`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_datacache.vhd#L178) and [`cpu.vhd:1106-1110`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L1106-L1110).

18. **Pitfalls to avoid, all present here:**
    - (a) The 64x64 multiplier is used multicycle without a multicycle SDC ([`cpu_mul.vhd`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_mul.vhd), [`N64.sdc`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/N64.sdc)).
    - (b) Silent architectural shortcuts taken for timing: 29-bit PC increment ([`cpu.vhd:2136`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L2136)), region check from base only ([`2257`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L2257)), unconditional I-cache index invalidate "HACK" ([`cpu_instrcache.vhd:216-219`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu_instrcache.vhd#L216-L219)).
    - (c) Every load bubbles regardless of dependency ([`cpu.vhd:2780`](https://github.com/MiSTer-devel/N64_MiSTer/blob/eb5554af01bb97bdf3d295aed02a989ac10ccee4/rtl/cpu.vhd#L2780)).
    - (d) Mult, div, FPU and TLB miss all freeze the entire pipe.
    - (e) The global `stall = 0` enable fans out to the whole core (it relies on physical-synthesis duplication).

    For a 603e, replace (c) and (d) with per-unit busy/valid plus completion-queue retirement, and turn (b) into an extra pipeline stage or a precise exception.
