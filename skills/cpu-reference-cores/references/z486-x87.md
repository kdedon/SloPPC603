## 1. FPU architecture overview

```
 CPU ─ESC/FOP, I/O-port protocol─► x87_bridge ─► x87_control ──operands (regs)──► x87_executor
       direct m32 demand read ───► x87_unit        │ command ROM (M10K)               │ sequencer
                                                   │ stack RAM 8×80 (M10K, 2 ports)   │ 256×64 ucode ROM (M10K)
                                                   ◄──── done + commit_action ────────┘
```

- **Coprocessor, not a pipeline unit.** Commands arrive over the 386/387 port protocol; a "direct m32" path
  lets the CPU fetch a fault-checked memory operand and hand it over without the port round trip
  ([`x87_unit.sv:45-52`](https://github.com/nand2mario/z486/blob/53dc450e01302c174f75fc9280417a4dc5884863/x87/x87_unit.sv#L45-L52),
  [`112-153`](https://github.com/nand2mario/z486/blob/53dc450e01302c174f75fc9280417a4dc5884863/x87/x87_unit.sv#L112-L153)).
  One arithmetic op executes at a time; there is no FP pipelining.
- **Internal format is binary64-class**: 15-bit extended exponent, **53-bit significand**, separate G/R/S
  bits, and a registered class tag ([`x87_pkg.sv:12-22`](https://github.com/nand2mario/z486/blob/53dc450e01302c174f75fc9280417a4dc5884863/x87/x87_pkg.sv#L12-L22)).
  This is an x87 approximation (real x87 carries 64 significand bits), but it makes the datapath width
  the same as PowerPC double, so its area is a fair comparison point for our FPU.
- **One horizontal microcoded executor** owns every numeric op: a 64-bit control word selects independent
  resource lanes (align, shared add, shift, prepare, classify, pack, engine, GRS, commit)
  ([`x87_ucode_pkg.sv:12-30`](https://github.com/nand2mario/z486/blob/53dc450e01302c174f75fc9280417a4dc5884863/x87/x87_ucode_pkg.sv#L12-L30),
  [`x87_executor.sv:1-4`](https://github.com/nand2mario/z486/blob/53dc450e01302c174f75fc9280417a4dc5884863/x87/x87_executor.sv#L1-L4)).

## 2. Datapath sharing (the reason it is ~5.6k ALMs)

- **One 68-bit work register and one adder** serve add/sub, rounding increment, and conversions. The adder's
  operands are either `work ± aligned-small` or `work + round_increment`
  ([`x87_executor.sv:52`](https://github.com/nand2mario/z486/blob/53dc450e01302c174f75fc9280417a4dc5884863/x87/x87_executor.sv#L52),
  [`227-240`](https://github.com/nand2mario/z486/blob/53dc450e01302c174f75fc9280417a4dc5884863/x87/x87_executor.sv#L227-L240)).
  Rounding is therefore a microstep on the same adder, not a separate incrementer per op.
- **No barrel shifter, no LZC tree.** Alignment shifts the smaller operand by 4 or 1 bit per cycle with a
  sticky fold ([`x87_executor.sv:1724-1736`](https://github.com/nand2mario/z486/blob/53dc450e01302c174f75fc9280417a4dc5884863/x87/x87_executor.sv#L1724-L1736),
  [`205-214`](https://github.com/nand2mario/z486/blob/53dc450e01302c174f75fc9280417a4dc5884863/x87/x87_executor.sv#L205-L214));
  normalization loops 1 bit per cycle until the leading one is in place
  ([`x87_executor.sv:793-801`](https://github.com/nand2mario/z486/blob/53dc450e01302c174f75fc9280417a4dc5884863/x87/x87_executor.sv#L793-L801)).
  The add/sub recipe is align-loop → add → normalize-loop → round → pack → finish
  ([`build_x87_microcode.py:312-333`](https://github.com/nand2mario/z486/blob/53dc450e01302c174f75fc9280417a4dc5884863/x87/build_x87_microcode.py#L312-L333)).
  Latency is data-dependent (tens of cycles on deep cancellation). Specials skip to finish via a
  registered-operand predicate ([`x87_executor.sv:571-574`](https://github.com/nand2mario/z486/blob/53dc450e01302c174f75fc9280417a4dc5884863/x87/x87_executor.sv#L571-L574)).
- **53×53 multiply as four 27×27 partial products** (Cyclone V's native 27×27 DSP mode → 4 DSP blocks),
  with limb carries propagated across microsteps: prepare registers limb 1, accumulate registers limb 2,
  the top limb and rounding follow ([`x87_executor.sv:242-258`](https://github.com/nand2mario/z486/blob/53dc450e01302c174f75fc9280417a4dc5884863/x87/x87_executor.sv#L242-L258),
  [`2200-2231`](https://github.com/nand2mario/z486/blob/53dc450e01302c174f75fc9280417a4dc5884863/x87/x87_executor.sv#L2200-L2231),
  recipe [`build_x87_microcode.py:340-350`](https://github.com/nand2mario/z486/blob/53dc450e01302c174f75fc9280417a4dc5884863/x87/build_x87_microcode.py#L340-L350)).
  No single cycle holds a 106-bit carry-propagate add. The DSP inputs are the executor's operand
  registers, loaded before `start` and held for the whole op
  ([`x87_control.sv:995-998`](https://github.com/nand2mario/z486/blob/53dc450e01302c174f75fc9280417a4dc5884863/x87/x87_control.sv#L995-L998)).
- **Divide and square root share one restoring recurrence**: one 58-bit subtractor, one result bit per
  cycle; the microcode picks divide or sqrt trial values
  ([`x87_executor.sv:260-275`](https://github.com/nand2mario/z486/blob/53dc450e01302c174f75fc9280417a4dc5884863/x87/x87_executor.sv#L260-L275),
  [`2121-2198`](https://github.com/nand2mario/z486/blob/53dc450e01302c174f75fc9280417a4dc5884863/x87/x87_executor.sv#L2121-L2198)).
  Both then reuse the shared pack/round lane.
- **Transcendentals in 28-bit limbs from a RAM scratch file**: 83-bit CORDIC state lives in two mirrored
  16×28 RAMs (2R1W), processed limb by limb
  ([`x87_cordic_scratch.sv:1-27`](https://github.com/nand2mario/z486/blob/53dc450e01302c174f75fc9280417a4dc5884863/x87/x87_cordic_scratch.sv#L1-L27)).
  Rare wide operations go through a narrow datapath instead of widening the common one.

## 3. Control: microcode as a checked, generated artifact

- **Sequencer**: a synchronous 256×64 ROM; next address = `start ? entry : flow(uop, condition)`, with
  NEXT/JUMP/BRANCH/LOOP/WAIT/FINISH ([`x87_sequencer.sv:26-66`](https://github.com/nand2mario/z486/blob/53dc450e01302c174f75fc9280417a4dc5884863/x87/x87_sequencer.sv#L26-L66)).
  Conditions are derived from registered executor state
  ([`x87_executor.sv:536-575`](https://github.com/nand2mario/z486/blob/53dc450e01302c174f75fc9280417a4dc5884863/x87/x87_executor.sv#L536-L575)).
- **The control store is M10K on both vendors**, explicitly. The Xilinx branch notes that the sparse `case`
  form otherwise becomes thousands of LUTs
  ([`x87_ucode_rom.sv:15-22`](https://github.com/nand2mario/z486/blob/53dc450e01302c174f75fc9280417a4dc5884863/x87/x87_ucode_rom.sv#L15-L22),
  Altera `altsyncram` ROM [`28-54`](https://github.com/nand2mario/z486/blob/53dc450e01302c174f75fc9280417a4dc5884863/x87/x87_ucode_rom.sv#L28-L54)).
- **The generator is the source of truth** and rejects words that drive the same datapath from two lanes,
  shift-vs-ALU conflicts, count-decrement conflicts and >256 words
  ([`build_x87_microcode.py:492-546`](https://github.com/nand2mario/z486/blob/53dc450e01302c174f75fc9280417a4dc5884863/x87/build_x87_microcode.py#L492-L546),
  [`602`](https://github.com/nand2mario/z486/blob/53dc450e01302c174f75fc9280417a4dc5884863/x87/build_x87_microcode.py#L602);
  [`x87/README.md:1-9`](https://github.com/nand2mario/z486/blob/53dc450e01302c174f75fc9280417a4dc5884863/x87/README.md#L1-L9)).
  Structural hazards inside a horizontal word are caught at build time, not in simulation.
- **Results are provisional until FINISH.** The executor never writes the stack; `done` returns a
  `commit_action`, and `x87_control` performs the architectural write
  ([`x87_executor.sv:50`](https://github.com/nand2mario/z486/blob/53dc450e01302c174f75fc9280417a4dc5884863/x87/x87_executor.sv#L50),
  [`x87_control.sv:1051-1060`](https://github.com/nand2mario/z486/blob/53dc450e01302c174f75fc9280417a4dc5884863/x87/x87_control.sv#L1051-L1060)).

## 4. FP register storage

- **8×80 stack in one true-dual-port M10K**, stored in raw architectural format; decode to the internal
  struct happens at the consumer so untouched values round-trip exactly
  ([`x87_stack_mem.sv:1-2`](https://github.com/nand2mario/z486/blob/53dc450e01302c174f75fc9280417a4dc5884863/x87/x87_stack_mem.sv#L1-L2),
  [`20-74`](https://github.com/nand2mario/z486/blob/53dc450e01302c174f75fc9280417a4dc5884863/x87/x87_stack_mem.sv#L20-L74);
  [`x87_control.sv:251-253`](https://github.com/nand2mario/z486/blob/53dc450e01302c174f75fc9280417a4dc5884863/x87/x87_control.sv#L251-L253)).
  Port B serves FXCH/FRSTOR; there is no reset of the array.
- The behavioural model mirrors the M10K new-data RDW on each port
  ([`x87_stack_mem.sv:76-95`](https://github.com/nand2mario/z486/blob/53dc450e01302c174f75fc9280417a4dc5884863/x87/x87_stack_mem.sv#L76-L95)).

## 5. Integer pipeline, caches, TLB (brief)

- **Two control paths from D2**: short "hardwired recipes" (1–3 µsteps) for common instructions, with
  successor **chaining** into the predecessor's last slot; microcode for the rest
  ([`hardwired_control.sv:1-7`](https://github.com/nand2mario/z486/blob/53dc450e01302c174f75fc9280417a4dc5884863/hardwired_control.sv#L1-L7),
  chain-safety rules [`189-200`](https://github.com/nand2mario/z486/blob/53dc450e01302c174f75fc9280417a4dc5884863/hardwired_control.sv#L189-L200)).
  Same fast-path/slow-path split as our branch unit and folding work, applied to issue.
- **Valid bit stored in the tag RAM word; each tag word read as one RAM read.** Separate valid/tag slices
  made Quartus 17 infer extra read ports and push the arrays into logic
  ([`l1_cache.sv:111-135`](https://github.com/nand2mario/z486/blob/53dc450e01302c174f75fc9280417a4dc5884863/l1_cache.sv#L111-L135)).
- **TLB**: per-way device classification in parallel with the hit (not after the PFN mux); four `KEEP`
  copies of the high-fanout live address, one per way; an independent RAM-read TLB for the D2 port
  ([`paging_tlb.sv:90-95`](https://github.com/nand2mario/z486/blob/53dc450e01302c174f75fc9280417a4dc5884863/paging_tlb.sv#L90-L95),
  [`103-117`](https://github.com/nand2mario/z486/blob/53dc450e01302c174f75fc9280417a4dc5884863/paging_tlb.sv#L103-L117),
  [`126-129`](https://github.com/nand2mario/z486/blob/53dc450e01302c174f75fc9280417a4dc5884863/paging_tlb.sv#L126-L129)).
- **Store ordering**: I/O and INTA do not overtake posted stores; framebuffer writes bypass the posted
  queue ([`memory.sv:187-191`](https://github.com/nand2mario/z486/blob/53dc450e01302c174f75fc9280417a4dc5884863/memory.sv#L187-L191)).
- **Vendor normalisation header**: one include maps feature macros to RAM-style, keep, noprune and
  replicate attributes per vendor, with the rule that they "must never change a visible cycle contract"
  ([`z486_platform.svh:36-58`](https://github.com/nand2mario/z486/blob/53dc450e01302c174f75fc9280417a4dc5884863/z486_platform.svh#L36-L58)).

## 6. Timing and build

- No multicycle constraints: iterative units stay single-cycle per step, so the FPU needs no SDC exceptions.
- Aggressive Quartus recipe (physical synthesis, retiming, register duplication, `MULTICORNER_ANALYSIS OFF`)
  ([`production_settings.tcl:1-29`](https://github.com/nand2mario/z486/blob/53dc450e01302c174f75fc9280417a4dc5884863/boards/de10nano/scripts/production_settings.tcl#L1-L29)).
  Multicorner off reports a single corner; compare against our slow-corner numbers with care.
- The FPU sequencer's next-address path runs from the unregistered M10K `q` through the condition mux into
  the M10K address register ([`x87_ucode_rom.sv:28-54`](https://github.com/nand2mario/z486/blob/53dc450e01302c174f75fc9280417a4dc5884863/x87/x87_ucode_rom.sv#L28-L54),
  [`x87_sequencer.sv:26-44`](https://github.com/nand2mario/z486/blob/53dc450e01302c174f75fc9280417a4dc5884863/x87/x87_sequencer.sv#L26-L44)).
  A likely limiter at higher clocks; not measured here.

## 8. Pitfalls

- **Incomplete x87**: 53-bit significand instead of 64; "sufficient to run DOS Quake" is the bar. Do not
  cite it for IEEE-completeness or flag semantics.
- **Variable, data-dependent latency** (align/normalize loops). Incompatible with a cycle-accurate
  603e contract unless placed behind a named parameter.
- **One op at a time**, no FP pipelining; fine for x87-era code, not for PowerPC's II=1 `fadd`/`fmul`.
- **Released clock (85 MHz) exceeds the reported Cyclone V Fmax (57.95 MHz)** in this repository.
- Several source headers point to `doc/z486/implementation_notes.md`, which is not in the repository.
- `tests/ucode.hex` is not Apache-licensed.

## 9. What is x87-specific and does not transfer

- The 8-entry register **stack**, TOP pointer, tag word, FXCH port, and the 387 I/O-port command protocol.
- CORDIC transcendentals, log/exp tables, FPREM, BCD store; PowerPC has none of these.
- Precision control (PC field) and the 80-bit memory format; PowerPC rounds to single or double only.
- x87 exception model (status word, `ERROR#`, deferred reporting at the next FP instruction). PowerPC needs
  FPSCR sticky/summary bits, FPRF, FR/FI and precise or imprecise enabled-exception modes.
- **No fused multiply-add.** PowerPC `fmadd` needs the full 106-bit product aligned with the addend and a
  single rounding; z486's datapath never holds that sum, so its area figure is a lower bound, not a target.
- x87 NaN rules (larger-significand selection, "indefinite") differ from PowerPC's first-NaN-in-order rule.

## Top transferable lessons for a 603e core (ranked)

1. **One shared work lane: normaliser, adder and rounder instantiated once.**
   - *Technique:* every op leaves its result in one wide work register with G/R/S; one adder performs both
     the significand sum and the rounding increment; one pack stage forms results.
   - *Evidence:* [`x87_executor.sv:227-240`](https://github.com/nand2mario/z486/blob/53dc450e01302c174f75fc9280417a4dc5884863/x87/x87_executor.sv#L227-L240), [`719-722`](https://github.com/nand2mario/z486/blob/53dc450e01302c174f75fc9280417a4dc5884863/x87/x87_executor.sv#L719-L722).
   - *603e:* conversions (`fctiw[z]`, `frsp`), divide and estimate results should reach the same rounder
     as `fadd`/`fmadd`, not own a rounder each. Keep one 3-stage pipe; do not copy the iterative loops.

2. **27×27 DSP limbs with carries spread over registered steps.**
   - *Evidence:* [`x87_executor.sv:242-258`](https://github.com/nand2mario/z486/blob/53dc450e01302c174f75fc9280417a4dc5884863/x87/x87_executor.sv#L242-L258), [`2200-2231`](https://github.com/nand2mario/z486/blob/53dc450e01302c174f75fc9280417a4dc5884863/x87/x87_executor.sv#L2200-L2231).
   - *603e:* double multiply already has two cycles; keep the product carry-save or limb-split so no stage
     carries a 106-bit CPA plus alignment. 4 DSP blocks for 53×53 is the Cyclone V floor.

3. **Divide and sqrt on one recurrence, shared with the final rounder.**
   - *Evidence:* [`x87_executor.sv:260-275`](https://github.com/nand2mario/z486/blob/53dc450e01302c174f75fc9280417a4dc5884863/x87/x87_executor.sv#L260-L275), [`2121-2198`](https://github.com/nand2mario/z486/blob/53dc450e01302c174f75fc9280417a4dc5884863/x87/x87_executor.sv#L2121-L2198).
   - *603e:* the 603e has no `fsqrt`, but `fdiv`/`fdivs` and the estimate sequences can share one
     recurrence. Radix-2 (1 bit/cycle) misses the 33-cycle double divide; retire 2 bits/cycle
     (two radix-2 steps or radix-4) to hold the contract.

4. **FP registers in block RAM, raw format, no reset, decode at the consumer.**
   - *Evidence:* [`x87_stack_mem.sv:20-74`](https://github.com/nand2mario/z486/blob/53dc450e01302c174f75fc9280417a4dc5884863/x87/x87_stack_mem.sv#L20-L74), [`x87_control.sv:251-253`](https://github.com/nand2mario/z486/blob/53dc450e01302c174f75fc9280417a4dc5884863/x87/x87_control.sv#L251-L253).
   - *603e:* 32×64 FPRs in MLAB copies (one per read port) with a funnelled write port remove ~2k flops and
     several 64-bit 32:1 read muxes.

5. **Horizontal microcode with a generator that rejects lane conflicts.**
   - *Evidence:* [`build_x87_microcode.py:492-546`](https://github.com/nand2mario/z486/blob/53dc450e01302c174f75fc9280417a4dc5884863/x87/build_x87_microcode.py#L492-L546).
   - *603e:* for rare sequences (denormal steps, estimate refinement, `mtfsf` corner cases) a small
     control table checked at build time beats hand-written FSMs. Store it in M10K, not a `case`.

6. **Operands registered and held for the whole op; results provisional until commit.**
   - *Evidence:* [`x87_control.sv:995-998`](https://github.com/nand2mario/z486/blob/53dc450e01302c174f75fc9280417a4dc5884863/x87/x87_control.sv#L995-L998), [`x87_executor.sv:50`](https://github.com/nand2mario/z486/blob/53dc450e01302c174f75fc9280417a4dc5884863/x87/x87_executor.sv#L50).
   - *603e:* matches our commit-gated FPR/FPSCR writes; multi-step units must read only their own captured
     operand registers, never a live forwarding bus.

7. **Narrow limb datapath for rare wide operations** (CORDIC in 28-bit limbs through a RAM scratch).
   - *Evidence:* [`x87_cordic_scratch.sv:1-27`](https://github.com/nand2mario/z486/blob/53dc450e01302c174f75fc9280417a4dc5884863/x87/x87_cordic_scratch.sv#L1-L27).
   - *603e:* candidates are `fres`/`frsqrte` refinement and integer conversions, if they are allowed a
     longer latency.

8. **Cheap tag-RAM discipline**: valid bit in the tag word, one read per word.
   - *Evidence:* [`l1_cache.sv:111-135`](https://github.com/nand2mario/z486/blob/53dc450e01302c174f75fc9280417a4dc5884863/l1_cache.sv#L111-L135).

9. **Replicate a high-fanout address with `KEEP` copies per consumer group.**
   - *Evidence:* [`paging_tlb.sv:103-117`](https://github.com/nand2mario/z486/blob/53dc450e01302c174f75fc9280417a4dc5884863/paging_tlb.sv#L103-L117).

10. **Area budget evidence:** a binary64-width FPU without FMA and without pipelining fits in about
    5.6k ALMs on Cyclone V ([`README.md:44-53`](https://github.com/nand2mario/z486/blob/53dc450e01302c174f75fc9280417a4dc5884863/README.md#L44-L53)).
    A pipelined FMA FPU with PowerPC semantics costs more; ~12k ALMs is plausible, 26k is not necessary.
