# Saturn_MiSTer SH-2 (SH7604) — microarchitecture techniques mined for a 603e core

Source: [MiSTer-devel/Saturn_MiSTer](https://github.com/MiSTer-devel/Saturn_MiSTer/tree/a23bbb22c8c9a43926ee2196875e257d225291b7). `core/` = `rtl/SH/core/`, `7604/` = `rtl/SH/SH7604/`. Links are pinned to the reviewed commit.
Clocking context: `clk_sys` = 57.27 MHz ([`rtl/pll/pll_0002.v:33`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/pll/pll_0002.v#L33)); the SH-2s run at clk_sys/2 = 28.6 MHz
using alternating `SYS_CE_R`/`SYS_CE_F` ([`Saturn.sv:668-670`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/Saturn.sv#L668-L670)). The CPU is cycle-accurate to the real chip, not built for maximum IPC.

**Build-file pitfall found first.** The files that actually get compiled are [`rtl/SH_mem.sv`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH_mem.sv) and [`rtl/SH7604_mem.sv`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH7604_mem.sv)
([`files.qip:4-5`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/files.qip#L4-L5)). The copies in the tree at [`core/SH_mem.sv`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_mem.sv) and [`7604/SH7604_mem.sv`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/SH7604_mem.sv) are **stale variants**: the regfile RAM there is 32 entries with a 5-bit address, and the tag RAM is an altsyncram 20 bits wide with the read clock inverted. The compiled tag RAM is an MLAB 19 bits wide with an asynchronous read, which is what [`CACHE.sv`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/CACHE.sv) needs.
Both sets define the same module names, so which one you get depends only on the qip. Lesson: keep exactly one definition per RAM primitive.

## 1. Pipeline organization

**Stages and registers.** Pipeline state is one typedef'd struct of per-stage structs ([`core/SH_pkg.sv:1332-1387`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_pkg.sv#L1332-L1387)):
```systemverilog
typedef struct { IFtoID_t ID; IDtoEX_t EX; EXtoMA_t MA; MAtoWB_t WB; WB_t WB2; } PipelineState_t;
// IDtoEX_t: IR, DI(DecInstr_t), PC, BC, RA, RB, R0   EXtoMA_t: IR, DI, PC, BC, RES, ADDR, WD
```
Every stage carries the **whole decoded record `DI` plus IR and PC** all the way to WB2. Later stages just test fields of `PIPE.<stage>.DI` for hazard, forwarding and port decisions, so no stage has to re-decode ([`core/SH_core.sv:631-641`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_core.sv#L631-L641), [`737-742`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_core.sv#L737-L742)).
`WB2` is an extra stage that exists only to supply forwarding data (see §3).

**Stall structure: a per-stage stall built from a few global causes, with no flush network** ([`core/SH_core.sv:114`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_core.sv#L114), [`195`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_core.sv#L195), [`201`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_core.sv#L201), [`256`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_core.sv#L256), [`610`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_core.sv#L610), [`721`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_core.sv#L721), [`780`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_core.sv#L780)):
```systemverilog
wire BUS_STALL = (MA_ACTIVE & BUS_WAIT) | (IF_ACTIVE & BUS_WAIT) | (VECT_ACTIVE & VECT_WAIT);
assign IF_STALL = BUS_STALL | INST_SPLIT | IFID_STALL;
assign ID_STALL = BUS_STALL | INST_SPLIT;
assign EX_STALL = BUS_STALL | INST_SPLIT;
wire   MA_STALL = BUS_STALL | MAWB_STALL;
```
- `BUS_WAIT` is the single backpressure input. The cache, the MULT unit (the MAC is modelled as a bus slave) and peripherals all OR into it ([`7604/SH7604.sv:240`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/SH7604.sv#L240): `.BUS_WAIT(CACHE_BUSY | (MULT_BUSY & ~FAST))`).
- `INST_SPLIT` is a one-cycle structural/hazard bubble. It freezes IF/ID/EX while MA/WB keep draining ([`core/SH_core.sv:180-191`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_core.sv#L180-L191)).
- `MAWB_STALL` is the complementary phase: it holds MA/WB after the split so the IF access can use the single bus.

**Hazard detection (load-use and bus contention)** ([`core/SH_core.sv:131-134`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_core.sv#L131-L134)):
```systemverilog
wire LOAD_ISSUE = (PIPE.EX.DI.MEM.R | (PIPE.EX.DI.MAC.R & ~PIPE.EX.DI.MEM.W)) &
   ((PIPE.EX.DI.RA.W & PIPE.EX.DI.RA.N == ID_DECI.RA.N & ID_DECI.RA.R) | ... RB ... | ... R0 ...);
wire INST_ISSUE = ((IFID_STALL & ~PC[1]) | ~PIPE.ID.PC[1]) & (EX has MEM.R|MEM.W|MAC.R|MAC.W) & ~ID_DECI.IID;
```
The load-use check compares the EX-stage load destination against the **ID-stage decoded source fields** (`ID_DECI.RA.R/RB.R/R0R`). It does not use raw IR bits. Because decode produces explicit "reads RA / reads RB / reads R0" flags, the hazard logic stays small and exact.
`INST_ISSUE` models the real SH-2 IF/MA contention. There is only one core bus, which fetches 32 bits (two instructions) whenever `PC[1]==0`. A data access in MA therefore steals a fetch slot. `IID` ("instruction issue disabled") lets decode suppress this for micro-sequenced ops.

**Forwarding: an explicit, priority-ordered bypass network with decode-directed overrides** ([`core/SH_core.sv:358-385`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_core.sv#L358-L385), [`430-511`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_core.sv#L430-L511)):
- Sources in priority order: MA.RES (EX→EX), RD_SAVE (load data saved during a split), WB.RD (load data), WB.RES, WB2.RESA, WB2.RESB. That is youngest first.
- ALU results and load results get separate match terms: `*_EXEX` excludes loads and `*_MALD`/`*_WBLD` match only loads. Loads return data a stage later, so each needs its own mux input.
- Instructions that write two registers (post-increment loads write Rn and Rm, carried as the RA and RB write ports) get the RB-port match qualified by `RA.N != RB.N | !RA.W`, so the load-data port wins when both name the same register ([`359`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_core.sv#L359)).
- **Decode-directed bypass (clever).** `DecInstr_t.DP` has `BPWBA`, `BPLDA` and `BPMAB` ([`core/SH_pkg.sv:78-80`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_pkg.sv#L78-L80)). These force a mux input no matter which register number is involved:
  ```systemverilog
  else if (BP_A_WBLD || PIPE.EX.DI.DP.BPLDA) BP_A = PIPE.WB.RD;   // SH_core.sv:436
  if (BP_B_EXEX || PIPE.EX.DI.DP.BPMAB)       BP_B = PIPE.MA.RES;  // SH_core.sv:454
  ```
  Micro-sequences use them to pass **temporaries through pipeline latches** without spending an architectural register. Examples: in the exception sequence, the vector-table load result feeds the next micro-op's PC write ([`core/SH_pkg.sv:219-224`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_pkg.sv#L219-L224)); in RTE, the popped PC feeds the next step ([`526-533`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_pkg.sv#L526-L533)); in TAS.B, the loaded byte feeds the OR and then the write-back ([`908-940`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_pkg.sv#L908-L940)).

**Branches and delay slots: resolved in EX, with squashing done by substituting a NOP at decode input rather than by a flush** ([`core/SH_core.sv:259`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_core.sv#L259), [`298-304`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_core.sv#L298-L304), [`123-124`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_core.sv#L123-L124)):
```systemverilog
wire ID_DELAY_SLOT = ~PIPE.EX.DI.BR.BI & (PIPE.EX.DI.BR.BT == CB | PIPE.EX.DI.BR.BT == UCB);
wire [15:0] DEC_IR = RES_EXP || INT_EXP ? 16'h0000 :
                     ID_DELAY_SLOT && !PIPE.EX.DI.BR.BD ? 16'h0009 :   // squash: NOP
                     IFID_STALL ? PIPE.EX.IR : PIPE.ID.IR;
if (PIPE.EX.DI.PCW && !EX_STALL) PC <= ALU_RES;                      // target from EX ALU
```
- A branch is decoded as a 2-state sequence. State 0 computes the target (PC write). State 1 is a marker micro-op with `BR.BI=0` that shows up in EX while the next instruction is in ID ([`core/SH_pkg.sv:1144-1164`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_pkg.sv#L1144-L1164)).
- For a delayed branch (`BD=1`) the slot instruction runs normally. For a non-delayed taken BT/BF (`BD=0`) the slot is replaced by NOP at decode input.
- The conditional branch is **resolved in ID using the T flag forwarded from EX**, so a CMP followed by BT has no bubble: `assign BR_T = PIPE.EX.DI.CTRL.W && PIPE.EX.DI.CTRL.S == SR_ ? SR_NEW.T : SR.T;` ([`core/SH_core.sv:302`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_core.sv#L302)). The not-taken case sets `LST=0`, a 1-cycle instruction; taken sets `LST=1`, which adds a bubble ([`core/SH_pkg.sv:1092-1101`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_pkg.sv#L1092-L1101)).
- The decoder flags illegal slot instructions itself: `if (!DS) ... else DECI.ILI = 1;` in every branch case.

**Multi-cycle instructions use a state counter in ID, and decode is a function of (IR, STATE)** ([`core/SH_core.sv:306`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_core.sv#L306), [`345-346`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_core.sv#L345-L346), [`235-249`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_core.sv#L235-L249)):
```systemverilog
wire [2:0] NEXT_STATE = STATE == ID_DECI.LST ? 3'd0 : STATE + 3'd1;
STATE <= NEXT_STATE; IFID_STALL <= |NEXT_STATE;     // hold IF while sequencing
// IF side: while a sequence runs, the newly fetched instruction parks in SAVE_ID
if (ID_DECI.LST == 3'd0) PIPE.ID <= {NEW_IR,PC}; else SAVE_ID <= {NEW_IR,PC};
if ((ID_DECI.LST != 0) && (STATE == ID_DECI.LST)) PIPE.ID <= SAVE_ID;
```
While `IFID_STALL` is set, the instruction being sequenced is re-decoded from `PIPE.EX.IR`, i.e. its own copy in EX. Each micro-step then issues a full `DecInstr_t` down the normal pipe, so the micro-ops reuse the ALU, AGU and MA paths unchanged.

## 2. Decode

- **The decoded control record is one packed struct of sub-structs and enums** ([`core/SH_pkg.sv:72-156`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_pkg.sv#L72-L156)): `Datapath_t DP`, `IMMType_t IMMT`, `ALU_t`, `Mem_t`, `Reg_t RA/RB`, `R0R`, `PCW`, `Control_t CTRL`, `MAC_t`, `Branch_t`, plus the flags `TAS`, `SLP`, `IBI` (interrupt-blocking), `IID`, `LST[2:0]` (last micro-state), `VECR` and `ILI` (illegal).
- **Default-then-override decode.** `DECI = DECI_RESET;` followed by per-opcode partial assignments using positional struct literals ([`core/SH_pkg.sv:190`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_pkg.sv#L190), e.g. `DECI.ALU = '{0, 1, ADD, 4'b0000, 3'b000}; DECI.MEM = '{ALURES, ALUB, IR[1:0], 1, 0, 1};`). `DECI_RESET` ([`158-175`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_pkg.sv#L158-L175)) is also what the pipeline registers load on reset, so a reset or bubble is simply "a decoded NOP".
- **Exceptions are pseudo-instructions in the same decode function.** Its inputs are `RES_EXP, INT_EXP, ILI_EXP, ILSI`. When one is active, decode ignores IR and emits a micro-sequence: reset is 6 states ([`194-236`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_pkg.sv#L194-L236)), interrupt 8 states ([`238-287`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_pkg.sv#L238-L287)), illegal instruction 7 states ([`289-334`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_pkg.sv#L289-L334)). In each, the SR and PC pushes are ordinary MEM.W micro-ops with SP pre-decrement done by the ALU (`ALU = '{0,1,ADD,4'b0001,...}` is subtract-1, scaled ×4 by `MEM.SZ`, see §11).
- **Version gating by a function argument.** `VER` (0 = SH-1, 1 = SH-2) makes SH-2-only opcodes decode as illegal on SH-1: `if (VER == 1 && !DS) ... else DECI.ILI = 1;` ([`361`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_pkg.sv#L361), [`392`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_pkg.sv#L392)). One decode table serves both cores.
- **Keeping decode off the critical path.** Decode is purely combinational in ID. Its output register fields `ID_DECI.RA.N/RB.N` drive the regfile read address directly ([`core/SH_core.sv:103-105`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_core.sv#L103-L105)), and the regfile is an async-read MLAB, so decode, the regfile read and the EX latch all happen in one CPU cycle. That works only because the CPU cycle is 2 × clk_sys with no multicycle SDC (§8). The chain is `PIPE.ID.IR → DEC_IR mux → Decode → RA.N → MLAB → PIPE.EX.RA`. Immediate extraction and scaling are deferred to EX: IMMT is only a 3-bit selector and EX builds the immediate from `PIPE.EX.IR` ([`core/SH_core.sv:402-421`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_core.sv#L402-L421)), so wide immediate muxing stays out of ID.
- **Operand-source encodings.** `RegSource_t` (GRX/SCR/BPC/IPC/TPC) chooses what feeds ALU input B: a GPR, a control register, the fetch PC, the PC of the EX instruction, or the PC of the saved next instruction. That lets exception and branch micro-ops push the correct return PC without extra datapath ([`core/SH_core.sv:476-483`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_core.sv#L476-L483)).

## 3. Register file

- 16 GPRs sit in **two MLAB copies (`altdpram`, `ram_block_type="MLAB"`, `rdaddress_reg="UNREGISTERED"`)**, one per read port, both written together ([`core/SH_regfile.sv:124-129`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_regfile.sv#L124-L129), [`rtl/SH_mem.sv`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH_mem.sv)). Reads are asynchronous, which gives the same-cycle read after decode.
- **The third read port is a flop copy of R0** ([`core/SH_regfile.sv:148-162`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_regfile.sv#L148-L162)). SH addressing modes such as `@(R0,Rn)` need three operands. Instead of a third MLAB copy, R0 is shadowed in flops and `R0_Q` is always available.
- **PR (the link register) is register 16, held in flops outside the RAM.** RAM writes are masked with `~ADDR[4]` and reads are muxed with `RA_ADDR[4] ? PR : RAMA_Q` ([`126`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_regfile.sv#L126), [`131-146`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_regfile.sv#L131-L146)). The RAM stays 16 deep; architecturally special registers go in flops.
- **The second write port is time-multiplexed onto the idle clk_sys cycle (clever, with a caveat).** Port B (the post-increment/second destination) is latched on CE and written on the next, non-CE clock ([`core/SH_regfile.sv:105-126`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_regfile.sv#L105-L126)):
  ```systemverilog
  wire  [4:0] W_ADDR = CE ? WA_ADDR : WB_ADDR_LATCH;
  wire [31:0] REG_D  = CE ? WA_D    : WB_D_LATCH;
  wire        REG_WE = (WAE & ~WA_ADDR[4] & CE) | (WBE_LATCH & ~WB_ADDR_LATCH[4]);
  ```
  This gives two write ports from a 1W MLAB for free, but it **requires CE ≤ clk/2**. With CE held high every cycle, port B would lose writes. The core also suppresses the WB write when RA.N == RB.N ([`core/SH_core.sv:816`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_core.sv#L816)).
- **No write-through bypass inside the RAM** (`read_during_write_mode_mixed_ports = "CONSTRAINED_DONT_CARE"`). Instead, **the WB2 pipeline stage keeps the just-written values** (RESA = port A value, RESB = port B value) and the EX bypass mux picks them up ([`core/SH_core.sv:372-377`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_core.sv#L372-L377), [`781-808`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_core.sv#L781-L808)). This is the standard answer for any FPGA regfile without read-during-write guarantees: add one more forwarding stage.
- Simulation uses a behavioural array selected by a `synopsys translate_off/on` + `` `define SIM`` trick ([`core/SH_regfile.sv:42-102`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_regfile.sv#L42-L102)). The synthesis branch uses the MLAB primitive.

## 4. MULT / DIVU

**MULT (the MAC unit) sits outside the core, reached through the MA stage as a pseudo-bus-slave** ([`7604/MULT.sv`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/MULT.sv), [`7604/SH7604.sv:266-291`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/SH7604.sv#L266-L291)):
- The core drives `MAC_SEL/MAC_OP/MAC_WE` from `PIPE.MA.DI.MAC` ([`core/SH_core.sv:827-830`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_core.sv#L827-L830)). Operands travel on the core write-data bus (`CBUS_DO`). For MAC.L/MAC.W they come from the cache read data instead (`MULT_DI = ... MAC_OP[3:2]==2'b10 ? CACHE_DO : CBUS_DO`), so memory operands flow straight from the D-side into the multiplier without a register-file round trip.
- Multi-operand instructions are 2-state micro-sequences that feed MA first and MB second ([`core/SH_pkg.sv:391-409`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_pkg.sv#L391-L409), [`682-700`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_pkg.sv#L682-L700)).
- **The DSP computes fast; a counter models latency (clever).** A single 33×33 signed product `SRES` plus a 64-bit accumulate is written one clk_sys after the operands latch (`MUL_EXEC` is not CE-gated, [`7604/MULT.sv:33-35`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/MULT.sv#L33-L35), [`127-163`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/MULT.sv#L127-L163)). Separately, `MM_CYC` is loaded with the real SH-2 latency (MUL.L = 4, MULS.W = 1, MAC.W = 2, MAC.L = 4) and counts down on CE_R ([`81`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/MULT.sv#L81), [`91`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/MULT.sv#L91), [`101`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/MULT.sv#L101), [`113`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/MULT.sv#L113), [`122-125`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/MULT.sv#L122-L125)).
- **Interlock only when needed.** `CBUS_BUSY = ~MM_DONE && (!MAC_OP[2] ? MAC_SEL[0] : |MAC_SEL);` ([`168`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/MULT.sv#L168)). The core stalls only if a later instruction touches MACH/MACL, or starts another multiply, before `MM_CYC` expires. Independent instructions overlap the multiply, exactly as the real chip does. `FAST` disables the interlock ([`7604/SH7604.sv:240`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/SH7604.sv#L240)).
- Saturating MAC (S bit) is handled inline, including the SH-2 quirk that MAC.W saturation sets MACH bit 0 ([`7604/MULT.sv:137-163`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/MULT.sv#L137-L163)).
- Caveat: the 33×33 multiply + 64-bit add runs as a single clk_sys path and is not pipelined through DSP registers. That closes at 57 MHz, but would need a DSP pipeline stage at 603e clock rates.

**DIVU (the memory-mapped divider) is an iterative restoring divider, 1 quotient bit per CPU cycle, using both clock phases** ([`7604/DIVU.sv:39-139`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/DIVU.sv#L39-L139)):
- The step counter runs 0..38 with 0x3F as idle. Steps 1/2 negate operands to magnitude, 3..35 do shift-subtract, 36/37 negate the results back, and an overflow check at step 5 exits early ([`123-127`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/DIVU.sv#L123-L127)).
- **Two-phase datapath split.** The CE_F phase selects `VAL/NEG` (a mux) and the CE_R phase does `NRES = (VAL^{65{NEG}}) + NEG` (the negate adder) ([`60-93`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/DIVU.sv#L60-L93)). Splitting the mux and the adder across half-cycles halves the logic depth per clk_sys edge. This is a general trick when CE = clk/2.
- **Access interlock.** Reading a DIVU register while `OPERATE` sets `BUSY`, which propagates as `IBUS_WAIT → CBUS_BUSY → core BUS_WAIT` ([`245-259`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/DIVU.sv#L245-L259)). Writes during operation are ignored ([`170`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/DIVU.sv#L170)). The chip's documented stall comes for free through the bus-wait path.
- The quotient shifts into DVDNTL during iteration, as the real hardware does, so a read during the operation returns intermediate values ([`190-192`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/DIVU.sv#L190-L192)).

The core's own `DIV1` step instruction is one ALU op: the adder gets `{ALU_A[30:0],SR.T}` and add/sub is selected by `M~^Q` ([`core/SH_core.sv:542-543`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_core.sv#L542-L543), [`650-653`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_core.sv#L650-L653)). DIV1 is not iterated in hardware because software loops it.

## 5. Cache ([`7604/CACHE.sv`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/CACHE.sv)) — 4 KB, 4-way, 16 B lines, 64 sets, write-through

**Organization**
- **Data array: four byte-lane M10Ks** (`CACHE_RAM` ×4, 1024×8 each, [`135-138`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/CACHE.sv#L135-L138)). The byte lanes give byte-enable writes without `byteena`. The address is `{way[1:0], A[9:2]}`, so all ways live in one RAM and **the way number forms the RAM's upper address bits**. The read way comes from `WayToAddr(WAY_HIT)` ([`131-132`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/CACHE.sv#L131-L132)), which means the hit way must be known before the data RAM address is registered.
- **Tags: four MLAB 64×19 copies, one per way, async read** ([`143-147`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/CACHE.sv#L143-L147), compiled definition [`rtl/SH7604_mem.sv`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH7604_mem.sv) altdpram MLAB). **Valid bits: four MLAB 64×1** ([`7604/CACHE.sv:151-155`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/CACHE.sv#L151-L155)). **LRU: two MLAB 64×6 copies**, one read by the fill/update address and one by the CPU address ([`7604/CACHE.sv:192-194`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/CACHE.sv#L192-L194)).
- **Hit logic is fully combinational off the core address** ([`7604/CACHE.sv:204-221`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/CACHE.sv#L204-L221)):
  ```systemverilog
  WAY_TAG[i] = CTAG_Q[i] == CBUS_A[28:10];
  WAY_HIT[i] = WAY_TAG[i] & CVALID_Q[i] & ~DIRTY[i];
  ```
  Timing: the core puts `CBUS_A` out after CE_R. The MLAB tags read asynchronously and the M10K data RAM registers its read address on the next clk_sys edge (the CE_F edge), so data is ready by the next CE_R. **One CPU cycle is two FPGA clocks: tag compare/way select in the first half, data RAM access in the second.** The cache FSM also acts on CE_F ([`7604/CACHE.sv:282`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/CACHE.sv#L282)).

**Flash invalidate uses a flop "dirty" bitmap over the RAM valid bits (clever)** ([`157-184`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/CACHE.sv#L157-L184)):
```systemverilog
reg [63:0] TAG_DIRTY[4];               // 1 = entry considered invalid
... if (CVALID_WE[i]) TAG_DIRTY[i][CACHE_WR_ADDR[9:4]] <= CACHE_LINE_PURGE;
else if (CCR.CP) TAG_DIRTY <= '{'1,'1,'1,'1};   // whole-cache purge in one clock
```
A RAM cannot be cleared in one cycle, so a 256-bit flop vector masks the RAM valid bits and resets in one clock. Any later write to a set clears its mask bit. `LRU_DIRTY[63:0]` does the same for the LRU RAM, forcing LRU to 0 after a purge ([`173-184`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/CACHE.sv#L173-L184), [`189`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/CACHE.sv#L189), [`199-201`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/CACHE.sv#L199-L201)). **This transfers directly to 603e `icbi`/`dcbi`/HID0[ICFI/DCFI] flash invalidate and to TLB `tlbia`.**

**6-bit pseudo-LRU (the SH-2's documented pairwise-order matrix)** ([`74-100`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/CACHE.sv#L74-L100)):
- `WayFromLRU` picks the victim with a `casez` on 6 pairwise "way i more recent than way j" bits. `LRUSelect` updates only the three bits touching the used way.
- Two-way mode (`CCR.TW`) restricts replacement to ways 2/3 using `lru[0]`. Ways 0/1 then serve as 2 KB on-chip RAM through the data-array window.
- The LRU is updated on every hit, write-hit and fill (`LRU_WE = CACHE_UPDATE | CACHE_WRITE | CACHE_READ | CACHE_ADDR_WRITE`, [`190`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/CACHE.sv#L190)) through a registered write address (`CACHE_WR_ADDR`), so the update lands one half-cycle after the access.

**Address-space-decoded cache control** ([`48-55`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/CACHE.sv#L48-L55)):
- `A[31:29]`: 000 cached, 001 uncached, 010 associative purge, 011 address array (tag/valid/LRU read-write), 100/110 data array (cache-as-RAM), 111 I/O.
- Purge: a write to the purge area clears valid in every way whose tag matches (`CACHE_WR_WAY <= WAY_TAG`, [`341-346`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/CACHE.sv#L341-L346)). Address-array writes set the tag, valid and LRU directly ([`141-150`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/CACHE.sv#L141-L150), [`189`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/CACHE.sv#L189)).
- The 603e has no memory-mapped cache arrays, but the same **"control operation as a pseudo-access through the normal MA path"** pattern fits `dcbf/dcbst/dcbi/icbi/dcbz`: decode them as special MEM ops that reach the cache FSM through the ordinary D-side request.

**Miss / line fill** ([`7604/CACHE.sv:296-314`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/CACHE.sv#L296-L314), [`373-394`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/CACHE.sv#L373-L394)):
- A read miss issues a 4-beat **burst** (`IBBURST=1`) to the BSC. It **starts at the longword after the missed one and wraps**: `IBADDR <= {A[31:4], A[3:2]+1, 2'b00}`, `ARRAY_POS <= A[3:2]`. It ends on the missed word, which reaches the core straight from the bus (`IBDATA_RDY → CBUS_DO = IBUS_DI`, [`427-429`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/CACHE.sv#L427-L429)). This is SH-2 order, the **opposite of critical-word-first**; the 603e does critical-word-first, so reverse the start offset.
- Each returning beat is written into the victim way (`CACHE_UPDATE`, chosen from LRU at miss time). `IBLOCK` holds the bus through the burst and drops on the beat before last.
- `CCR.ID`/`CCR.OD` (instruction-fill or data-fill disable) gate the update by access type using the core's `BUS_ID` ([`313`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/CACHE.sv#L313)).

**Write policy: write-through, no allocate, one posted write** ([`7604/CACHE.sv:317-340`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/CACHE.sv#L317-L340), [`430`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/CACHE.sv#L430)):
- Every write to cached, uncached or I/O space goes to the bus. A write hit also updates the array.
- `CBUS_BUSY = CBUS_REQ && (IBUS_READ || IBUS_READARRAY || IBUS_READ_PEND || IBUS_WRITE_PEND);` The core is not stalled for the write itself, only when a second access arrives while the first is still outstanding. That is **a one-entry write buffer in effect**.
- TAS.B (`CBUS_TAS`) forces an uncached, locked read-modify-write ([`359`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/CACHE.sv#L359), [`366`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/CACHE.sv#L366)).

**IBUS_PREREQ: a miss hint one half-cycle early** ([`437`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/CACHE.sv#L437)) tells the BSC a CPU miss is coming, so it can defer the DMAC (`DBUS_SKIP`, [`7604/BSC.sv:908`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/BSC.sv#L908)). This is a cheap priority hint.

## 6. Bus state controller ([`7604/BSC.sv`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/BSC.sv)) and multi-master arbitration

- **Three request ports into one external bus**: CBUS (CPU via cache), DBUS (DMAC) and VBUS (interrupt-vector fetch), plus internal refresh. Priority in the grant block is refresh > vector > DMAC > CPU. CPU/DMA fairness comes from `DBUS_SKIP`, which alternates and is set by the CPU pre-request ([`774-790`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/BSC.sv#L774-L790), [`886-906`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/BSC.sv#L886-L906)). `*_LOCK` holds ownership across atomic sequences (TAS, DMA bursts, cache line fills).
- **Explicit enum bus-cycle FSM**: `T0, T1, T2, TW` (SRAM), `TRAS, TWCAS, TRCAS, TRD, TWNOP, TRFS1, TRFS2` (SDRAM) and `TV1, TV2` (vector) ([`188-193`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/BSC.sv#L188-L193)). **Wait states come from programmable registers** through small lookup functions `GetAreaW/GetAreaIW/GetAreaLW/GetAreaSZ` indexed by `A[26:25]` (area) ([`87-133`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/BSC.sv#L87-L133)). External `WAIT_N` is then sampled in TW ([`301-315`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/BSC.sv#L301-L315)).
- **Two-edge bus timing.** Strobes are asserted on CE_R and data is latched and strobes deasserted on CE_F ([`317-327`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/BSC.sv#L317-L327), `DATA_LATCH` → `DAT_BUF` at [`473-495`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/BSC.sv#L473-L495)). Using both half-cycles reproduces the real pin timing.
- **Bus sizing.** 8/16-bit areas break a 32-bit access into several beats using a `NEXT_BA` byte-lane-remaining mask and a `DAT_BUF` assembled per lane ([`473-495`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/BSC.sv#L473-L495), [`510-560`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/BSC.sv#L510-L560)). The parameters `SIZE_BYTE_DISABLE/SIZE_WORD_DISABLE` prune the unused sizing logic when the board has only 32-bit memory ([`Saturn.sv:342`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/Saturn.sv#L342)).
- **Posted writes.** On write start the requester's busy is cleared immediately (`if (DBUS_WE) DBUSY <= 0;`, e.g. [`664`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/BSC.sv#L664)), so the CPU or DMAC continues while the FSM finishes the write cycle.
- **How the core stalls on the bus**: `CBUS_BUSY = CBUSY | CBUSY2 | ((BUS_RLS | (BGR & MASTER) | (~BREQ & ~MASTER)) & CBUS_EXT_REQ) | ((DBUS_ACTIVE|VBUS_ACTIVE|REFRESH_ACTIVE) & ~CBUS_PER_REQ);` ([`1045`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/BSC.sv#L1045)). That goes to cache `IBUS_WAIT`, then `CACHE_BUSY`, then core `BUS_WAIT`. On-chip peripheral accesses (`CBUS_PER_REQ`, `A[31:16]==FFFF`) **bypass external-bus ownership**, so the CPU can reach its own peripherals while the other SH-2 owns the bus.
- **Master/slave SH-2 arbitration** is pin-level and faithful ([`7604/BSC.sv:922-963`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/BSC.sv#L922-L963)):
  - `MD[5]` selects the mode. The master asserts `BGR` (grant) when the other side requests (`BRLS`), the FSM is in `T0` and no locked transfer is running (`BUS_END`). It then sets `MST_BUS_RLS` to float its pins.
  - The slave raises `BREQ` when it has work, takes the bus on `BACK`, and gives it back once idle.
  - **Pin muxing for bus release** is done in the SoC wrapper ([`7604/SH7604.sv:563-566`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/SH7604.sv#L563-L566)): `assign {A,DO} = !BUS_RLS ? {IA,IDO} : {EA,EDO};`. When the master releases, its external pins pass through the `E*` inputs.
  - In Saturn, **the chain is SCU-DMA → SSH E-pins → MSH E-pins → system bus** ([`Saturn.sv:369-381`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/Saturn.sv#L369-L381), [`425-446`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/Saturn.sv#L425-L446)). The DCC block arbitrates the slave SH-2 against the SCU ([`rtl/Saturn/DCC.sv:57-71`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/Saturn/DCC.sv#L57-L71)). This avoids tristates entirely: each "released" master is a mux stage.
- **Accuracy/performance escape hatches**: `FAST` skips programmed wait counts ([`303`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/BSC.sv#L303), [`398`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/BSC.sv#L398), [`444`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/BSC.sv#L444), [`Saturn.sv:483`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/Saturn.sv#L483), [`895`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/Saturn.sv#L895) OSD `status[28]`), and `AREA_TIMIMG[area]` ("1-wait for low-latency memory", [`7604/BSC.sv:2`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/BSC.sv#L2)) changes how `WAIT_N` is honoured per area.
- The `A55A` write key for BSC registers is modelled ([`986`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/BSC.sv#L986)).

## 7. Exceptions and interrupts

- **INTC priority uses a prefix-max chain** ([`7604/INTC.sv:135-175`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/INTC.sv#L135-L175)). Sources are tested in fixed hardware order (NMI, UBC, IRL, DIVU, DMAC, WDT/BSC, SCI, FRT). Each stage stores the running maximum level in `IP[k]`, and a later source wins only if its level is strictly greater **and** above `INT_MASK`:
  ```systemverilog
  if (DIVU_IRQ && IPRA.DIVUIP > INT_MASK && {1'b0,IPRA.DIVUIP} > IP[2]) begin
     IP[3] = ...; IP[4] = ...; ...; INT = DIVU_INT; end
  ```
  Ties resolve to the earlier source, which matches the chip's default priority. The result is registered every clk_sys into `INT_ACTIVE`, and the level/vector come from small case tables ([`178-220`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/INTC.sv#L178-L220)). NMI uses level 16, above any mask.
- **Handshake with the core**:
  - The core asserts `INT_ACP` when it accepts ([`core/SH_core.sv:833`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_core.sv#L833)), gated by: not blocked by the previous instruction (`IBI`, e.g. LDC/STC/STS), not in a delay slot, not mid-sequence and no stall.
  - The INTC snapshots `INT_ACCEPTED <= INT_ACTIVE` and `IRL_LVL_SAVE` on `INT_ACP` ([`7604/INTC.sv:236-241`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/INTC.sv#L236-L241)), so the vector stays stable while a higher-priority request arrives later.
  - The core latches `INT_LVL` into `INT_LVL_LATCH` for the SR.I update ([`core/SH_core.sv:281-283`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_core.sv#L281-L283), used by the `IMSK` SR-set at [`667`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_core.sv#L667)).
  - `INT_ACK` = the VECR micro-op leaving MA, which clears the accepted source.
- **External vector fetch** (IRL in external-vector mode): the `VECR` micro-op raises `VECT_REQ → INTC VBREQ → BSC VBUS → TV1/TV2 cycle with IVECF_N`. `VECT_WAIT` stalls the core through `BUS_STALL` ([`core/SH_core.sv:174-178`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_core.sv#L174-L178), [`7604/INTC.sv:224-247`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/INTC.sv#L224-L247), [`7604/BSC.sv:449-468`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/BSC.sv#L449-L468)).
- **Sequencing in the pipeline.** Exceptions are **decoded pseudo-instructions** (§2). `DEC_IR` is forced to 0x0000 and the exception flags choose the micro-program:
  - Interrupt micro-program ([`core/SH_pkg.sv:238-287`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_pkg.sv#L238-L287)): (1) push SR (SP−4), (2) push PC (`IPC`), (3) SR.I ← level plus vector acknowledge, (4) load `VBR + vec*4`, (6) PC ← loaded value via `BPLDA`, (7) delay marker.
  - The vector number enters as immediate type `VECT`, muxed in EX from `RES_EXP ? {~NMI_N,0} : INT_REQ_LATCH ? INT_VEC : ILI_EXP ? 4|ILSI<<1 : IR[7:0]` ([`core/SH_core.sv:397-400`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_core.sv#L397-L400)). TRAPA uses the same path with `ZIMM8`.
  - The illegal-slot variant pushes `TPC` (the branch target) instead of the slot PC ([`core/SH_pkg.sv:304`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_pkg.sv#L304)).
- **NMI** is edge-detected with a selectable edge (`ICR.NMIE`) and cleared on `INT_ACP` ([`7604/INTC.sv:88-106`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/INTC.sv#L88-L106)). **IRL** is accepted only after 4 identical samples (a glitch filter, [`108-132`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/INTC.sv#L108-L132)).
- **Address-error exceptions are not implemented**; a grep finds no misalignment trap. The byte-lane logic silently rotates misaligned accesses. For a 603e (alignment exception, DSI/ISI from the MMU) this gap must not be copied. Use the same pseudo-instruction mechanism, but trigger it from MA-stage fault signals (precise), not only from ID.

## 8. Timing / fmax and cycle accuracy

- **Clocking**: one fast clock with two complementary enables, `CE_R` (rising half) and `CE_F` (falling half) = clk_sys/2 each ([`Saturn.sv:668-670`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/Saturn.sv#L668-L670)). The core register file and all pipeline registers use `CE` = CE_R ([`7604/SH7604.sv:226`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/SH7604.sv#L226)). Peripherals, cache and BSC use **both phases**: requests are accepted and registers written on CE_R, and read data is registered on CE_F (the `REG_DO` pattern in every peripheral, e.g. [`7604/DIVU.sv:224-243`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/DIVU.sv#L224-L243), [`7604/INTC.sv:318-338`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/INTC.sv#L318-L338), [`7604/BSC.sv:1020-1040`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/BSC.sv#L1020-L1040)). Read data is therefore registered locally and ready by the next CE_R, with no combinational peripheral-to-core path.
- **Saturn.sdc has no CPU multicycle constraints** (it contains only Hq2x/ascal). Every SH-2 path is timed as a single 57 MHz clk_sys cycle, and the design relies on logic depth staying under 17.5 ns. The CE_R/CE_F split and the half-cycle RAM trick are what keep that possible. Lesson: if you use CE/2, either design every path for one fast clock (as here) or add explicit multicycle constraints, never leave it ambiguous.
- **Cycle accuracy is kept by modelling, not by slowing down the logic**:
  - The single core bus with IF/MA contention is modelled (`INST_ISSUE`, `MAWB_STALL`).
  - Multiply latency is counted, not computed slowly (§4).
  - Peripheral read wait states are explicit (WDT adds a 2-cycle `BUSY` shift register, [`7604/WDT.sv:208-245`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/WDT.sv#L208-L245); DIVU busy).
  - BSC wait states follow WCR/BCR1.
- **Global pause**: `EN` gates every CE use (`.EN(~DBG_PAUSE)`, [`Saturn.sv:739`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/Saturn.sv#L739); `else if (EN && CE)` throughout the core). This freezes the whole CPU without touching clocks.
- **Synchronous CPU reset beside the async power-on reset**: `RST_N` is async and `RES_N` (the CPU reset pin, synchronized on CE_R, [`7604/SH7604.sv:210-220`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/SH7604.sv#L210-L220)) is applied as `else if (!RES_N)` in each block. Reset re-enters the reset micro-program (`RES_EXP`), which fetches PC/SP from the vector table exactly like the chip.
- **The internal prescaler** is one 13-bit counter producing `CLK2_CE .. CLK8192_CE` with wildcard compares `DIV_CNT ==? 13'b...111` ([`7604/SH7604.sv:369-421`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/SH7604.sv#L369-L421)). Every peripheral timer selects from these; nobody makes its own divider.

## 9. SoC structure and reuse

- **Internal bus = a shared address/data broadcast plus a per-peripheral `*_ACT` select and a priority mux** ([`7604/SH7604.sv:327-342`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/SH7604.sv#L327-L342)):
  ```systemverilog
  assign IBUS_DI   = INTC_ACT ? INTC_DO : DIVU_ACT ? DIVU_DO : DMAC_ACT ? DMAC_DO : ... : BSC_IBUS_DO;
  assign IBUS_WAIT = INTC_ACT ? INTC_BUSY : DIVU_ACT ? DIVU_BUSY : ... : BSC_IBUS_BUSY;
  ```
  Each peripheral decodes its own range (`wire REG_SEL = (IBUS_A >= 32'hFFFFFF00 && IBUS_A <= 32'hFFFFFF3F)`, [`7604/DIVU.sv:34`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/DIVU.sv#L34)) and exports `ACT`, `DO` and `BUSY`. The default target is the BSC, i.e. external memory.
- **Register definition pattern** ([`7604/SH7604_pkg.sv:4-104`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/SH7604_pkg.sv#L4-L104)): each register gets a packed struct with named fields, plus `*_WMASK`, `*_RMASK` and `*_INIT` parameters. Writes are `REG <= DI & REG_WMASK`, reads return `REG & REG_RMASK`, and reset loads `REG_INIT`. Reserved-bit behaviour then lives in one place. Byte-lane writes use `IBUS_BA` per half-word ([`7604/INTC.sv:279-300`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/INTC.sv#L279-L300)).
- **Core reuse across SoCs**:
  - `SH_core #(.VER(0))` in SH7034 (the SH-1 in the CD block, [`rtl/SH/SH7034/SH7034.sv:276`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7034/SH7034.sv#L276), used from [`rtl/Saturn/CD/SH1.sv`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/Saturn/CD/SH1.sv)) versus the default `VER=1` in SH7604.
  - The core itself knows nothing of caches, MMIO or the bus protocol. Its bus is a minimal `A/DI/DO/WR/BA/REQ/ID/TAS/WAIT` interface plus the MAC and INTC side-bands ([`core/SH_core.sv:12-37`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_core.sv#L12-L37)). SH7034 wires `CBUS` straight to its internal bus with no cache ([`SH7034.sv:310-350`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7034/SH7034.sv#L310-L350)); SH7604 inserts `CACHE` between them.
  - Each SoC has its own `*_pkg.sv` and peripheral modules. The core package `SH2_PKG` is shared, and the qips include `../core/*` ([`SH7034.qip`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7034/SH7034.qip), [`SH7604.qip`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/SH7604.qip)).
- **Feature pruning by parameter.** `UBC_DISABLE`, `SCI_DISABLE` and `WDT_DISABLE` gate the peripheral's register process with `&& !DISABLE` ([`7604/SCI.sv:81`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/SCI.sv#L81)), so synthesis removes the logic. Saturn instantiates both SH-2s with UBC and SCI disabled ([`Saturn.sv:342`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/Saturn.sv#L342), [`412`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/Saturn.sv#L412)).

## 10. Debug / verification

- A `` `ifdef DEBUG`` port set on the core reads registers through the regfile read port A when `EN` = 0: `assign REGS_RAN = EN ? ID_DECI.RA.N : DBG_REGN;` ([`core/SH_core.sv:100-104`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_core.sv#L100-L104), [`839-864`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_core.sv#L839-L864)). **The debug register read borrows the real read port while the CPU is paused**, at zero cost to the normal build.
- `DBG_REGQ` also exposes SR, GBR, VBR and `PIPE.WB.PC` (the retiring PC). The breakpoint logic is stubbed out (`DBG_BREAK <= 1` is commented out, [`857`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_core.sv#L857)), so it is dead code.
- The regfile has a DEBUG-only shadow flop array exposing R0..R15/PR as ports ([`core/SH_regfile.sv:165-198`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_regfile.sv#L165-L198)), useful for waveform debugging.
- `// synopsys translate_off` blocks carry simulation-only state: `LOAD_SPLIT` ([`core/SH_core.sv:81-83`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_core.sv#L81-L83), [`154-160`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_core.sv#L154-L160)), a known regfile init pattern `'h01234567,'h11111111,...` ([`core/SH_regfile.sv:71`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_regfile.sv#L71)) and MAC init `01234567/89ABCDEF` ([`7604/MULT.sv:58-61`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/MULT.sv#L58-L61)). A recognisable reset pattern makes use of uninitialised registers easy to spot in traces.
- **No savestate support** in the SH-2. There are no `SS_*` ports, and the MLAB/M10K contents (regfile, cache) would not be captured.

## 11. Other HDL techniques worth extracting

- **ALU as package functions** `Adder/Log/Ext/Shifter(a, b, ci, code)` ([`core/SH_pkg.sv:1421-1498`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_pkg.sv#L1421-L1498)), driven by a 4-bit `CD` code from decode:
  - The adder handles add, sub, addc, subc, neg, cmp and dt through `b ^ {32{code[0]}}` and carry-in select `ci2 = code[1] ? ci ^ code[0] : code[0]`: one 32-bit adder, no separate subtractor.
  - Compare results `eq/ge_hs` for signed and unsigned are derived from the same adder ([`core/SH_core.sv:545-548`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_core.sv#L545-L548)).
  - `Log` implements and/xor/or/mov with optional inversion.
- **Operand scaling by access size in the immediate path**: `IMM_VAL = MEM.SZ ? imm<<1/<<2`, and branches use `<<1` ([`core/SH_core.sv:413-421`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_core.sv#L413-L421)). Displacement and SP-decrement micro-ops reuse `ONE`, scaled by `SZ` = long, to get ±4. For a 603e, handle `D`-form displacement and `lwzu`-style update the same way, through decode-selected immediate types.
- **Byte-lane data alignment functions**: `ByteShiftRigth` plus sign-extend by size for loads ([`core/SH_core.sv:701-719`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_core.sv#L701-L719)). Stores replicate data across lanes and set the byte enables with `4'b0001 << ~ADDR[1:0]` (big-endian, [`757-775`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_core.sv#L757-L775)). The 603e is big-endian by default, so this carries over directly; add the little-endian address munging (XOR of low address bits) as a separate stage-local step.
- **Address/write-data source selectors in the decoded record** (`MEM.ADDS/WDS` ∈ {ALUA, ALUB, ALURES}, [`core/SH_core.sv:588-608`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_core.sv#L588-L608)). Pre-decrement uses the ALU result as the address, post-increment uses the unmodified register as the address while the ALU produces the +N writeback. The same MA request logic serves every addressing mode.
- **Positional struct literals** (`'{SP, 1, 1}`) make decode rows compact but brittle: reordering a struct field silently breaks every row. Prefer named literals (`'{N:SP, R:1, W:1}`) in a new design.
- **Pitfalls seen**:
  - Blocking `=` register writes inside a clocked block ([`7604/INTC.sv:279-309`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/INTC.sv#L279-L309)). They work here but invite simulation/synthesis mismatch.
  - `SAVE_ID` and `RD_SAVE` have no reset branch, and `PIPE.MA.PC` is not reset under `RST_N` ([`core/SH_core.sv:203-243`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_core.sv#L203-L243), [`613-619`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_core.sv#L613-L619)).
  - Stale duplicate RAM modules (see top).
  - `always @(posedge CLK)` with no reset for `INT_ACTIVE` ([`7604/INTC.sv:135`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/INTC.sv#L135)).

## Top transferable lessons for a 603e core (ranked)

1. **Carry one packed `DecInstr_t` (struct of sub-structs and enums) through every pipeline stage, and do hazard, forwarding and port logic only from its fields.**
   *Why:* decode happens once; later stages test explicit `R/W/N` flags, not IR bits; reset or bubble is just `DECI_RESET`.
   *Evidence:* [`core/SH_pkg.sv:72-175`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_pkg.sv#L72-L175), [`1332-1387`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_pkg.sv#L1332-L1387); [`core/SH_core.sv:131-133`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_core.sv#L131-L133), [`358-385`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_core.sv#L358-L385).
   *603e:* define `dec_t` with `src_a/src_b/src_c` {N, R}, `dst[2]` {N, W} (update forms write RA plus RT), `unit` (IU/SRU/LSU/BPU/FPU), `mem`, `cr_field`, `serialize`, `lst`. Carry it in dispatch-queue entries and the completion queue, so rename, issue and completion never re-decode.

   *Why:* every micro-op reuses the normal ALU/AGU/LSU path; no separate microsequencer datapath.

3. **Treat exceptions and interrupts as injected pseudo-instructions decoded into a micro-program.**
   *Why:* the SR/PC save, the vector load and the jump all reuse the pipeline with no bespoke exception datapath.
   *Evidence:* `DEC_IR` force at [`core/SH_core.sv:298-300`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_core.sv#L298-L300); sequences at [`core/SH_pkg.sv:194-334`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_pkg.sv#L194-L334).

4. **Decode-directed bypass flags (`BPLDA/BPWBA/BPMAB`) pass micro-op temporaries through pipeline latches.**

5. **Build the GPR file from replicated async-read MLABs (one copy per read port). Put special or odd ports in flops (the R0 shadow gives a third read port, PR sits at index 16), and add a final "WB2" forwarding stage in place of RAM read-during-write bypass.**

6. **Time-multiplex a second RAM write port onto the idle fast-clock cycle when the pipeline runs at CE = clk/2.**
   *Why:* 2W from a 1W RAM at no area cost.

7. **Cache hit path: tags and valid bits in async-read MLAB (per-way copies, combinational compare), data in M10K with way bits as the upper address bits, and data RAM address registered at the mid-cycle edge.**
   *Why:* hit/way-select and data read both finish in one CPU cycle without a registered-tag bubble.

The TLB/BAT lookup in parallel with the tag read is the 603e analogue of `WAY_TAG`.

8. **Flash-invalidate with a flop "dirty/invalid-mask" bitmap over RAM-held valid bits.**
   *Why:* a RAM cannot be cleared in one cycle; a 256-bit flop vector can, and each later write clears its bit.
   *Evidence:* [`7604/CACHE.sv:157-184`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/CACHE.sv#L157-L184), [`199-221`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/CACHE.sv#L199-L221).

9. **Implement pseudo-LRU with the SH-2 6-bit pairwise matrix (`WayFromLRU` casez victim select plus a 3-bit update), stored per set in MLAB, with a read port for the CPU address and another for the fill address.**

20. **Warnings to carry forward.**
    - Keep exactly one definition per RAM primitive; the stale [`core/SH_mem.sv`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/core/SH_mem.sv) and [`7604/SH7604_mem.sv`](https://github.com/MiSTer-devel/Saturn_MiSTer/blob/a23bbb22c8c9a43926ee2196875e257d225291b7/rtl/SH/SH7604/SH7604_mem.sv) disagree with the compiled copies.

    - Prefer named struct literals over positional ones in decode tables.
    - No blocking assignments in clocked register-write blocks.
