# CPU TLB seed registers

This note records the round-2 register increment. The instruction follow-up is
[CPU_TLB_LOAD.md](CPU_TLB_LOAD.md).

`ENABLE_TLB_LOAD=1` makes the 603e DCMP (SPR 977), ICMP (SPR 981), and RPA (SPR 982) registers available through the existing CPU `mfspr`/`mtspr` path. The switch defaults off, requires `ENABLE_LIVE_CONTEXT=1` and `ENABLE_SUPERVISOR_EXCEPTIONS=1`, and is independent of `ENABLE_TLB_INVALIDATE`. This round adds only three 32-bit software-visible registers. It does not execute `tlbld`/`tlbli`, alter either TLB bank, capture an architectural page miss, or handle a page fault.

The local *MPC603e & EC603e RISC Microprocessors User's Manual* (`../1997_MPC603EUM_MPC603e_EC603e_Users_Manual.pdf`) lists the selectors in Table 2-39 (one-based PDF pages 121–122 / printed 2-43–44). Section 2.1.2.3 (PDF 87–88 / 2-9–10) describes ICMP/DCMP as read/write compare registers; §2.1.2.5 (PDF 89 / 2-11) describes RPA as read/write. Section 5.5.2.1 (PDF 232–234 / 5-36–38) places these registers in supervisor-only table-search software. No miss has been generated by this profile, so all three values begin at zero on the local core reset and change only on software writes.

The decoder accepts exact `mfspr` XO 339 and `mtspr` XO 467 forms for these selectors. Following the project's existing 603e policy from UM §2.3.5.1 (PDF 118 / 2-40), `mftb` XO 371 aliases `mfspr` for each newly implemented selector; this addition does not expand XO 371 legality for unrelated selectors. The two 5-bit SPR selector halves are reversed in the instruction encoding as described by UM §2.3.6.2.2 (PDF 121 / 2-43). A valid form in user mode becomes a privileged-instruction program exception **before allocation**, with no GPR or seed-register effect. Disabled selectors and unsupported encodings retain the existing diagnostic path.

`ppc_special` stores each full 32-bit value, including fields reserved or interpreted by a later TLB load. It returns the committed value on an accepted read and writes only on the matching instruction's retirement edge. A held retirement cannot update early; a canceled instruction cannot update; a later read sees the committed write. The state is local to the core, not a duplicate of the router's TLB or segment-register bank. The existing full-width SRR1 (SPR 27) read/write path can separately seed manual bit 14/WAY (HDL bit 17) for a future `tlbld`/`tlbli` round.

The reserved fields, ICMP/DCMP V/H/API, and RPA R/C/WIMG/PP have no effect in this round. Future CPU TLB loads must validate their supported input shape, enforce IR=DR=0 for the bounded profile, and use a retirement-owned prepared refill against the single external TLB service. The separate normalized management refill interface remains a test/control mechanism, not a CPU `tlbld`/`tlbli` substitute. The broader source audit and three-round dependency plan are in [TLB_REFILL_DEPENDENCIES.md](TLB_REFILL_DEPENDENCIES.md).
