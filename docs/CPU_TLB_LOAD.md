# CPU software-seeded TLB load

With `ENABLE_TLB_LOAD=1`, the core executes the 603e `tlbld rB` and `tlbli rB` instructions using software-written DCMP/ICMP/RPA and SRR1.WAY state. The switch defaults off and requires live supervisor context. It is independent of the CPU `tlbie` switch, but an integrated page-hit system must attach the single external TLB owner. This is a bounded **software-seeded** load: no architectural page-miss entry, DMISS/IMISS/HASH generation, TGPR, PTE search, or PTE R/C memory write is implied.

The local *MPC603e & EC603e RISC Microprocessors User's Manual* (`../1997_MPC603EUM_MPC603e_EC603e_Users_Manual.pdf`) §2.3.8, one-based PDF pages 125–126 / printed 2-47–48, gives primary opcode 31 and XO 978 (`tlbld`) or 1010 (`tlbli`). The exact accepted instruction masks are `(insn & 32'hffff_07ff) == 32'h7c00_07a4` and `32'h7c00_07e4`: manual fields 6–15 and Rc are zero, and only manual rB bits 16–20 (HDL `insn[15:11]`) vary. The full old GPR value, including r0, supplies EA. Valid user-mode forms become privileged-instruction program exceptions before allocation; malformed/reserved-field forms remain unsupported diagnostics. Neither instruction writes a GPR or flags.

UM §5.4.3.1, PDF 222–223 / 5-26–27, gives the TLB organization: manual EA15–19 selects a set (HDL `EA[16:12]`), VSID and EA4–14 form the tag, and SRR1.WAY chooses one of two ways. UM §2.1.2.3, PDF 87–88 / 2-9–10, says the high TLB word uses the upper 25 compare-register bits plus 11 bits of rB EA; §5.5.2.1.2, PDF 233 / 5-37, more generally describes loading the compare word. For this software-seeded profile, the CPU accepts only values for which those descriptions agree: selected DCMP/ICMP V=1, H=0, and API[5:0] equals rB EA4–9 (`rB[27:22]`). RPA reserved manual bits 20–22 and 29 must be zero. MSR.IR and MSR.DR must both be zero, matching the manual's recommended real-mode execution. A failed check produces a local diagnostic result **without offering a TLB request**; it makes no claim about silicon behavior for other software seeds or translated execution.

At dispatch the special lane snapshots the old rB, selected compare register, RPA, committed SRR1.WAY, and the supported-mode check. It retains an 85-bit normalized payload: bank (0 instruction, 1 data), EA[31:0], VSID=`CMP[30:7]`, way=`SRR1[17]`, RPN=`RPA[31:12]`, C=`RPA[7]`, WIMG=`RPA[6:3]`, PP=`RPA[1:0]`. RPA.R is ignored. API agreement allows the existing service to form the full tag from rB[27:17]; the low five extra tag bits come from rB[21:17]. A later seed-register or SRR1 write cannot alter this captured request.

The core/router boundary is separate `tlb_fill_req_valid/ready`, the captured payload fields, held `tlb_fill_rsp_valid/ready/error`, `tlb_fill_commit`, `tlb_fill_abort`, held `tlb_fill_ack_valid/ready`, and `tlb_fill_idle`. The router uses committed PR and translates the CPU request to service kind 5 (`PREPARE_REFILL`), distinct from the already-authorized normalized management refill. The core holds its existing MMU frontend fence, drains old fetch and memory obligations, and prepares without changing a TLB entry. A killed offered request completes its handshake before abort; held responses drain. An accepted matching retirement pulse commits a successful proposal exactly once, then the CPU waits for the held acknowledgment and refetches at the latest retained target. A response error, including router provenance failure after a successful underlying prepare, goes through abort and idle drain; it never commits. A local malformed-seed diagnostic never acquires router ownership and uses the context-abort path if canceled.

This profile does not reproduce the 603e's TLB replacement algorithm: software chooses the way through SRR1. The single TLB service retains its local duplicate-tag rejection and reset policy. Software must establish valid PTE R/C state and obey its own synchronization rules. The longer architectural miss/refill dependencies are recorded in [TLB_REFILL_DEPENDENCIES.md](TLB_REFILL_DEPENDENCIES.md).
