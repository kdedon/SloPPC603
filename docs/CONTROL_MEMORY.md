# Serialized control flow and real-mode memory

This temporary milestone prioritizes executable programs before returning to the original integer-family queue. It adds a conservative control/memory lane that drains older work, allocates an ordinary tagged completion entry, and blocks younger dispatch until retirement or cancelled-response drain. It is functional bring-up, not a 603e BPU/LSU timing implementation.

## Implemented scope and sources

- `b`, `bc`: relative/absolute and link variants; `bclr`, `bcctr`: link variants. BO/BI conditions, CTR decrement/zero tests and old LR/CTR targets are implemented. LK updates LR even when a conditional branch is not taken. Outside trace mode they take the branch unit, not the serialized lane; see [Branch unit](#branch-unit).
- `mflr`, `mfctr`, `mtlr`, `mtctr`: the SPR8/9 subset of `mfspr`/`mtspr`. Other SPR selectors remain unsupported by this implementation.
- `cmp`, `cmpl`, `cmpi`, `cmpli`: 32-bit comparisons to any BF-selected CR field, preserving all other fields and XER. Reserved bits and L=1 are rejected. Compares no longer use this lane; see [Compares](#compares).
- `lbz`, `lhz`, `lha`, `lwz`, `stb`, `sth`, `stw`, plus their non-update indexed forms: aligned, uncached, big-endian transfers through an abstract data interface. Update, multiple/string, reservation, byte-reversed and floating-point memory forms remain unsupported.

Primary 603e UM encodings are Table A-22 (PDF384), A-13 (PDF381), A-14 (PDF382), A-26 (PDF385), XL form A-37 (PDF394), XFX form A-38 (PDF395), and SPR Figure 2-1/descriptions (PDF81–82). Shared instruction semantics use tagged 601UM evidence: branches PDF575–578, BO Table 3-25 PDF190–191, SPR moves PDF679/690, and scalar load/store instruction descriptions PDF639–759. These secondary sources are not timing oracles.

Valid BO values are 0–5, 8–13, 16–20; the gaps and 21–31 are reserved. BCCTR permits only 4, 5, 12, 13 and 20, because it cannot decrement its target register. XL bits 15:11 and reserved Rc bits in X/XFX forms must be zero. Metadata retains these restrictions explicitly.

## State and ordering

Ordinary integer operations retain the reservation-station/IU path. The serialized lane reads committed operands after the completion queue and integer pipeline drain. Its third GPR read supplies store data independently of the address operands. No new speculative SPR or memory forwarding is claimed.

All operations still finish by completion slot and generation. Nongpr-writing instructions allocate completion entries without allocating GPR rename registers. BF is carried in the allocated retirement packet; the existing exact-tag flag owner protects comparison state. LR/CTR writes occur only on the matching retirement handshake. In trace mode (MSR[SE] or MSR[BE]) a taken branch redirects on the edge after its commitment, from a registered special-unit state, as a whole-machine recovery of the then-empty completion queue, and discards old sequential fetch traffic. The special unit stays busy through that edge, so a taken branch occupies one more cycle than at commit-edge redirect. The internal branch redirect takes priority over an external test redirect; the external acceptance output reports only acceptance of that external request.

## Compares

Compares are ordinary renamed IU operations, not serialized special uops. They wait for their GPR sources through the reservation station like any other IU operation and never drain the machine. The IU issues ~rA + B + 1 (B - rA) on its adder: EQ is operand equality; unsigned GT is the absence of carry-out; signed GT is the sum sign XOR overflow; LT is neither. SO is the committed XER[SO] captured at dispatch (PEM Table 2-3, PDF 69; Section 4.2.1.2, PDF 167-168; `cmp`/`cmpi`/`cmpl`/`cmpli`, PDF 442-445). A compare writes no GPR and takes the exact-tag flag token, so it still waits for an older flag writer to retire and blocks a younger flag reader or writer until it retires. Its result packet carries the CR nibble; completion shifts it into BF.

Latency: a compare with ready operands finishes one cycle after issue, the IU single-cycle class (603e UM Table 6-4, PDF 270). Before, it waited for the CQ and IU to empty, then spent one cycle in the special lane; that drain is gone, so older IU work and the compare now overlap. The reservation-station stage adds one cycle from dispatch to finish, so a compare feeding a branch (which then still drained) cost one more cycle than before. Compiled firmware shows both effects: the 1,515-retirement BE program, a compare-and-branch loop, takes 9,083 cycles instead of 8,999; the 29-retirement BE smoke takes 200 instead of 207 and fetch-fault 1,132 instead of 1,151; the other 21 profiles are unchanged. Compares still take no dual-issue or SRU path.

## Branch unit

Outside trace mode `b`, `bc`, `bclr` and `bcctr` neither drain the machine nor enter the serialized lane:

- Dispatch resolves the branch from the committed LR, CTR and CR. A branch waits while an uncommitted older branch writes the LR or CTR it reads (tracked by the youngest writer's completion tag, or an empty queue), and while the flag owner is uncommitted, unless the owner is an IU operation whose result has arrived: the branch then reads the committed CR merged with that result. The owner is the only uncommitted CR writer, so the merge is exact until it retires.
- The branch allocates a completion entry and passes through the IU as an add of zero and its next PC, which the retirement packet carries. On retirement LR takes PC + 4 (LK) and CTR decrements (BO[2] clear), and the committed next PC becomes the branch's next PC, so an interrupt at that boundary saves the branch outcome.
- A `b`, or a `bc` predicted taken, folds: on the edge after it enters the IQ, fetch redirects to its target and the word behind it in the fetch register is dropped. The prediction is taken for branch-always BO, otherwise backward unless the y bit reverses it.
- A `bclr` or `bcctr` predicted taken (branch-always BO, or the y bit set) folds the same way to the committed LR or CTR, but only when no older instruction still writes that register (603e UM §6.4.1.1, PDF 260-261: an `mtspr` LR/CTR, a counting `bc` or a linking branch ahead of it stops the fold). Writers are counted while in the IQ and tracked from dispatch to retirement (`lr_pending_q`, `ctr_pending_q`, which now include `mtlr` and `mtctr`), so the target cannot change before the branch dispatches; an assertion checks that the next queued word is at the resolved target. Otherwise the branch waits for the register at dispatch as before. A branch with LK reads the old LR or CTR and still writes LR at retirement.
- Shadow LR (UM §6.4.1.1): a linking branch's LR value, its PC + 4, is known when it is queued. When the youngest LR writer still in flight is a linking branch, a `bclr` folds to that value and, at dispatch, resolves from it instead of waiting for the writer to retire. An `mtlr` in flight, or a recovery, clears the shadow; the branch then waits as above. A folded `bclr` in DQ1 still needs no LR writer pending.
- Speculative dispatch (UM §6.4.1.2): a branch whose CR owner has not finished (an IU, SRU or serialized CR writer; no FP CR write outstanding) no longer waits. It dispatches on its prediction (the fold decision: taken when folded), and younger work dispatches behind it. It resolves when its owner's result is captured or the owner commits; until then neither it nor anything younger completes, a store behind it is not authorized, a younger access is offered speculative (only cacheable accesses are performed, and the serialized lane adopts none), and serialized-lane work waits. One level: a second CR branch waits. A correct prediction just releases completion. A wrong one stops dispatch, and on the next edge everything younger than the branch is removed through the completion queue's pivot recovery and fetch redirects to the real next PC (UM 6.4.1.2); older work continues. The branch keeps its entry and retires later with that PC (so SRR0 at its boundary is the real target); a second CR branch waits until it has. `ENABLE_BRANCH_SPEC` (default 1) turns speculation off; `ENABLE_BRANCH_EARLY_RECOVERY` (default 1, ignored with the FPU, which discards all its work on any recovery) set to 0 restores recovery after the branch retires.
  Verification: [dual dispatch slice 7](DUAL_DISPATCH_DESIGN.md#slice-7) (`test-core-branch-fold`, `test-core-machine-check-trace`).
- A taken unfolded branch, or a folded one that falls through, redirects fetch on the edge after dispatch to its resolved next PC, clears the fetch register and IQ, and blocks dispatch for that edge. No completion-queue recovery happens: everything younger than the branch is still in the IQ.
- Branch removal (`ENABLE_BRANCH_REMOVAL`, sim `BRANCH_REMOVAL=1`): a branch that needs no SPR write back is retired by the BPU (UM §6.3.1, PDF 253 / 6-7: "If no write back is needed, the branch instruction is retired"; §6.4.1.1, PDF 260 / 6-14). The removed set is `b`, and `bc`, `bclr`, `bcctr` with LK clear and BO[2] set (no CTR decrement), resolved at dispatch. A plain `b` (unconditional, no LK) is removed as it would enter the IQ: it folds there and takes no IQ entry or dispatch slot, and the next IQ entry counts it; dependency bits then compare that entry with the one before the `b`. The others are removed at dispatch: no CQ entry, no IU slot and no station; a removable branch in DQ1 (a folded `b` or branch-always) takes no CQ entry either, and DQ1 then allocates at the tail. Kept in the CQ: linking or counting branches (they write LR or CTR at retirement), a branch dispatched on a prediction (its entry is the misprediction pivot and gates younger completion), any branch in trace mode (MSR[SE] or MSR[BE]: UM §4.5.11, PDF 189 / 4-31, traces every completed instruction or branch, and trace mode takes the serialized path), a fetch fault or IABR match on the branch (a fault packet, not a branch), and every 602 branch. The manual lists no exception a removed branch can raise. An interrupt at the boundary after a removed branch saves the branch's own address (the committed next PC), so the branch runs again after `rfi`; it writes nothing, so that is exact. A recovery override is kept across a removed branch for the same reason. The next packet's `removed_branches` counts the removed branches just before it (at most three; a fourth takes an entry), which the retirement traces use to step a reference over them.

Outside a speculative dispatch, branches are speculative only in fetch. An older fault, interrupt or external recovery removes the branch with the rest of the queue, and its LR/CTR effects never happen. A fetch fault on the target is carried with that word and taken only if it dispatches. Instruction fetch may therefore run ahead of older stores; software orders a fetch after a store's side effect with `sync; isync`, as the architecture requires. Trace mode keeps the serialized path, because its trace boundary is precise; changing MSR refetches, so no folded entry is queued when trace mode starts (an assertion checks that a folded entry dispatches only to the branch unit).

## Data interface

A request has valid/ready, write, aligned 32-bit word address, 32-bit write data and four byte enables. Big-endian byte offset zero uses enable bit 3 and data bits 31:24; offset three uses bit 0 and bits 7:0. Loads extract the addressed byte/halfword from the returned word; LHA sign-extends the selected halfword. Effective addresses wrap at 32 bits. rA=0 means a literal zero base, while indexed rB=0 and store/source r0 are ordinary register reads.

Every accepted request, including stores, receives one response with valid/ready, 32-bit data and an error bit. Response ready is asserted only after the request acceptance has been registered. A responder may produce an immediate response but must hold it until accepted. A store error acknowledgment must indicate that the store had no external effect; the core cannot undo a peripheral write.

Only one data obligation is outstanding. A held request cannot be withdrawn or changed. Killing a load before an offer cancels it locally; killing an already offered load retains the offer, then drains and discards the response, including any error. New instructions remain blocked until the old obligation drains. Repeated redirects may change the eventual fetch target without assigning an old response to new work.

## Store authorization and faults

A store waits for `retire_ready_i` to authorize a latched reservation; a plain store may dispatch behind older work that has not retired, but its request waits until it is the completion-queue head, because the 603e performs a store only after every older instruction completes (UM §1.1.4.3, PDF 51 / 1-11: stores "are held in the store queue until the completion logic signals"; [PERFORMANCE.md](PERFORMANCE.md#store-ordering-fix)). Its request is offered only after that edge. Reservation authorizes the external memory effect and makes the store irrevocable through the later response and retirement handshake. Lowering ready afterward must not retract the request or permit cancellation. The final retirement handshake records completion; it is distinct from the earlier external-effect authorization. This is an explicit extension of the retirement-ready contract.

Misaligned halfword/word accesses produce a diagnostic before any data request. Error responses produce an ordered diagnostic without a load destination write. Killed errors produce no diagnostic. Faults still use the bootstrap halt mechanism: exception vectors, MSR/DAR/DSISR, translation, caches and physical 60x bus handling remain later work. Reset clears state and valid outputs; the environment must cancel its pre-reset memory obligations.

## Verification

The symbolic program generator emits 631 instruction words and an independent 579-retirement path. Its interpreter executes operation names and arguments rather than decoding those words. The core test passes 44,883 checks of exact PC/word, all 32 GPRs, full CR/XER/LR/CTR and byte-memory digest. It executes 31 loads, 22 stores, a counted accumulation loop, calls/returns, all comparison families and BF selectors, all AA/LK combinations, canonical BO condition/count combinations (including CTR zero/wrap), aligned old LR/CTR targets, signed loads, aliases, negative displacement and 32-bit address wrap. Backpressure includes 60 stalled data-request cycles and 151 stalled retirement cycles.

The edge fixture passes 799 checks: four misalignment diagnostics with no request, load/store error acknowledgments, cancelled held/accepted loads and coincident errors, repeated redirects during drain, store authorization/protection through request/response/retirement stalls, killed linking branches and a committing branch winning over an external redirect.

Compiled decoder validation passes 15,808 probes with 615 accepted, including BO/BI/reserved-XL combinations and all 1,024 SPR selectors for both move directions and Rc values. All 26 previous RTL targets, both new targets, core/wrapper lint and 120 Python tests pass. Independent review accepts the final bounded implementation. The matrix now has 90 reviewed entries: 80 implemented and 10 pending; 50 Appendix A source rows have bounded reconciliation and 176 retain full-mask transcription pending. The two SPR-move rows are reconciled only for selectors 8/9.

Faulted loads retain their rename allocation through terminal halt until reset. Resumable exceptions must reclaim it explicitly. No branch prediction/folding, pipelined LSU timing, update/split-unaligned forms, translation or FPGA closure is credited here.
