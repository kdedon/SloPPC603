# MPC603e bus transfer encoding contract

**Status:** bounded P02d1 source transcription and decoder metadata. This file completes the selected Chapter 7 transfer-command and transfer-size tables. It does not complete address alignment, endian lane steering, termination collisions, or bus RTL/BFM behavior.

The authoritative source is the local *MPC603e & EC603e RISC Microprocessors User's Manual*, `1997_MPC603EUM_MPC603e_EC603e_Users_Manual.pdf` (MPC603EUM/AD, 11/97). The tables were inspected as rendered pages so bit columns, bold instruction names, and the `TBST` overbar were not inferred from text extraction.

Machine-readable metadata is in `sim/spec/bus_encodings.json`. Query and validation code is in `sim/tools/bus_decode.py`; source-backed unit tests are in `sim/tools/test_bus_decode.py`.

| 7-2, Snoop Hit Response | PDF 287 / 7-11 | Every TT row and 603e action on a snoop hit. |

The TT transcription contains 26 printed pattern rows. The two `1XX01` and `1XX11` rows preserve `X` at `TT1` and `TT2`; expansion produces all 32 five-bit values exactly once. Nineteen expanded values are defined commands and thirteen are reserved. Ten Table 7-1 rows identify transactions generated by the generic 603e master table. Table 7-3 adds or refines three PID7v HID0[ABE] source mappings. “Generated” means the table associates the command with a processor transaction source; cache state, global-page, privilege, and instruction execution conditions still apply.

## Bit and status conventions

Bits appear in manual order: TT patterns are `TT0 TT1 TT2 TT3 TT4`, and size patterns are `TSIZ0 TSIZ1 TSIZ2`. PowerPC bit 0 is the most-significant named bit. Reversing these strings for conventional least-significant-bit indexing would decode a different command.

`TBST` is an active-low pin. The metadata and CLI accept logical `asserted` or `negated`, avoiding a false positive-level formula. For `eciwx` and `ecowx`, the four physical signal levels `TBST,TSIZ0,TSIZ1,TSIZ2` carry EAR[28:31] as a resource ID instead of a transfer size.

The decoder keeps four distinct outcomes:

- `defined`: valid 60x command or listed Table 7-5 size.
- `reserved`: TT value marked Reserved in Tables 7-1 and 7-2.
- `unsupported_by_profile`: valid bus command which the selected 603e master table does not generate.
- `unlisted`: asserted-`TBST`/`TSIZ` combination absent from Table 7-5. It is not silently promoted to Reserved or treated as a size.

The Table 7-2 snoop action is an action **on an address hit**. An `N/A` entry remains `not_applicable`; the decoder does not invent a cache transition. Full WIM-conditioned state behavior remains in the later snoop/cache contract.

### PID7v HID0[ABE] address-only overlay

When HID0[ABE] is set, Table 7-3 gives these PID7v address-only encodings:

| TT0..TT4 | Command | Transaction sources |
|---|---|---|
| `00000` | Clean block | `dcbst` |
| `00100` | Flush block | `dcbf` |
| `01100` | Kill block | `dcbz`, `dcbi` |

The `--pid7v-abe` decoder option applies this overlay only to master generation. It does not change the command identity or snoop interpretation. The ordinary Table 7-1 Kill-block association with `dcbz` remains present without the overlay. Detailed global-page and cache-state conditions are outside these encoding tables.

## TBST and TSIZ transfer sizes

Table 7-5 contains nine combinations:

| Logical `TBST` | TSIZ0..TSIZ2 | Meaning |
|---|---|---:|
| asserted | `010` | burst, 32 bytes |
| negated | `000` | 8 bytes |
| negated | `001` | 1 byte |
| negated | `010` | 2 bytes |
| negated | `011` | 3 bytes |
| negated | `100` | 4 bytes |
| negated | `101` | 5 bytes |
| negated | `110` | 6 bytes |
| negated | `111` | 7 bytes |

The repeated `TSIZ=010` is resolved by logical `TBST`: asserted is a 32-byte cache-line burst; negated is a two-byte nonburst transfer.

Chapter 8 §8.6.1, PDF 346–347 / printed 8-38–8-39 supplies the bounded data-width interpretation:

| Listed bus transfer | 64-bit bus | 32-bit bus |
|---|---:|---:|
| 32-byte cache-line burst | four 8-byte beats | eight 4-byte beats |
| aligned 8-byte nonburst | one beat | two beats, with `TBST` negated |
| 1–4 byte nonburst | one normal aligned bus-transfer beat | one bus-transfer beat |
| 5–7 byte nonburst | one normal aligned 64-bit tenure | unresolved here; requires alignment/decomposition tables |

The utility has no address input. Every defined size result therefore reports `address_alignment_status=not_checked` and `program_access_decomposition_status=not_checked`. A beat count describes the listed Table 7-5 bus transfer, not the number of transactions needed for an instruction/program access. The 5–7-byte 32-bit cases remain `mode_status=unresolved_without_alignment_tables`; the utility does not guess. Address-only transactions report size `not_applicable`. External-control operations report the four-bit resource ID derived from the raw physical levels, with logical asserted `TBST` corresponding to resource bit 0.

## Decoder use

Run from the repository root:

```sh
python3 sim/tools/bus_decode.py validate
python3 sim/tools/bus_decode.py tt 01010 --role master
python3 sim/tools/bus_decode.py tt 01010 --role snoop
python3 sim/tools/bus_decode.py tt 00000 --role master --pid7v-abe
python3 sim/tools/bus_decode.py size --tbst negated --tsiz 000 --bus-width 32
python3 sim/tools/bus_decode.py size --tbst asserted --tsiz 101 --bus-width 64 --context external_control
```

Queries print stable, sorted JSON. Malformed bit strings, invalid bus widths, invalid contexts, overlapping metadata patterns, missing TT codes, or stale expected counts fail deterministically. A reserved TT query succeeds with `encoding_status=reserved`; it is a valid query about an unusable encoding. An unlisted size query succeeds with `status=unlisted` and no inferred byte count.
