# Translated instruction-cache verification

`tb/tb_core_bat_cached_bus60x.sv` exercises the composed `ppc_core_bat_cached_bus60x` through public 60x pins and delayed target responses. The literal 41-retirement CPU program starts in real mode and installs four BAT mappings through MTSPR: an identity instruction mapping for context activation, a nonidentity cacheable instruction alias `EA 0x10000000 → PA 0`, a nonidentity instruction alias with WIMG=`2` for scalar bypass `EA 0x20000000 → PA 0`, and a data alias `EA 0x30000000 → PA 0`. External mapping management is inactive.

After MTMSR enables IR/DR, the program branches to `EA 0x10000100`. The pin monitor sees physical line bursts at `PA 0x100` and `0x120`, requires cacheable burst TT/TC/TBST/CI/TSIZ, and checks hit/miss pulses. Sequential instructions in the filled lines retire without individual physical fetches. The program loads `EA 0x30001000` from physical `0x1000`, increments the word, and stores it at physical `0x1004`; the responder checks scalar bus address and the exact big-endian 64-bit data lane. It then branches to `EA 0x20000200`, where WIMG=`2` must issue scalar instruction transactions at physical `0x200`, `0x204`, `0x208`, and `0x20c` with CI asserted. No line burst for physical `0x200` is permitted. SC enters the real-mode vector and RFI returns to the translated bypass code. Exact retirement PCs, instruction words, load values, handler context, final registers, and physical byte memory are checked under periodic retirement backpressure.

The isolated strict `verilator --binary --timing --assert -Wall` run passes: 41 retirements, 42 physical address offers, four line bursts, 15 cache-hit pulses, four miss pulses, five translated scalar bypass offers, one data read, one data write, and 3,342 checks. Run the canonical target with `make -C sim test-core-bat-cached-bus60x`.

This gate proves the translated physical address and BAT WIMG select the local line-cache or scalar-bypass path for the allowed pages it exercises. It does not establish automatic instruction coherence, HID0 or `icbi` semantics, pipelined or coherent bus behavior, or arbitrary page-table translation. The separate gate below covers remap, explicit maintenance, and denied-page cases.


## Remap, stale code, and permission gate

`tb/tb_core_bat_cached_bus60x_coherence.sv` runs a separate CPU program. It installs IBAT1 as a cacheable alias `EA 0x10000100 → PA 0x100`, executes an instruction that writes `r14=11`, then changes IBAT1L at retirement to map the same EA to `PA 0x20100`. Executing that EA now writes `r14=22`; both physical lines have the same cache set index, and the pin monitor requires one burst for each distinct PA. The CPU next stores the instruction word for `r14=33` through a DBAT alias onto physical `0x20100`. Even after `sync` and `isync`, a third execution retires the old cached `r14=22` instruction. The pin monitor verifies the exact big-endian scalar store and that no replacement line burst occurred.

An external cache invalidation request then drains and holds its completion. An accepted external all-kill redirect restarts the frontend at an identity-mapped instruction after the maintenance; releasing completion permits the fourth alias execution. It refills physical `0x20100` and retires the fresh `r14=33` instruction. The CPU then writes IBAT1L with PP=`00`, removing instruction permission while that line is warm. The following alias fetch retires a precise `FETCH_ISI_PROTECTION` at `EA 0x10000100`. A read-only check on the accepted physical fetch path and the managed-cache request path rejects any probe for `PA 0x20100`; the public 60x monitor also rejects any physical offer or line fill for it. The forbidden code continuation is unreachable.

The isolated strict `verilator --binary --timing --assert -Wall` run passes: 65 retirements, 34 physical address offers, one old-line burst, two new-line bursts, four successful alias executions, 14 stale-phase hit pulses, and 2,275 checks. The test applies periodic retirement backpressure and checks held retirement packets. Run the canonical target with `make -C sim test-core-bat-cached-bus60x-coherence`.

The maintenance sequence is an explicit external integration interface followed by an accepted frontend redirect. The test does not claim that `sync`, `isync`, BAT remapping, or a data store automatically invalidates the instruction cache.
